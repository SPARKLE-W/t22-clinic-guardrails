使用 Python 3.12，按代码目录的 `requirements.lock` 安装依赖。应用及完整测试需要 MySQL 8.4；当前实现尚不需要 RabbitMQ。私密配置、数据库和虚拟环境放仓库外。完整测试命令在 `05_系统代码` 目录执行：

```text
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test tests governance clinic --noinput -v 2
```

`.github/workflows/ci.yml` 在隔离的 MySQL 服务中运行上述检查，测试库固定为 `t22_app_test`。自动测试不进行正式性能验收，也不代表老师认可或人工业务审批。

## Git 与协作

`main` 保存可复现的稳定版本；新开发在 `feat/...`，修错在 `fix/...`。每批先做相关测试、提交有意义的改动，再推送并通过 Pull Request 合并；批末运行完整回归。无需每个环节调多个代理审批。涉及需求、权限或验收口径变化仍按既有人工决策流程处理。

主分支保护已启用：禁止强推和删除，必须通过PR及GitHub Actions的`regression`检查，分支需与主分支同步，未完成讨论需处理；管理员同样适用，批准人数为0。下一批范围见[Issue #2](https://github.com/SPARKLE-W/t22-clinic-guardrails/issues/2)。

首次提交导入现有真实成果；此前的开发经历由文档和原始证据记录，不追补虚构的历史提交。仓库保持私有，未添加开放许可。

GitHub 保存代码、当前需求/设计及精选证据。老师/同学原始文件、全文课堂副本、大量运行原始数据、历史导出预览、账号口令和数据库不上传；它不是本地课程材料的完整备份。历史文档保留本机绝对路径，在线阅读优先使用本页相对链接；排除的原始证据仍在本地 `10_验收证据` 中，提交课程作业时按清单另行打包。
