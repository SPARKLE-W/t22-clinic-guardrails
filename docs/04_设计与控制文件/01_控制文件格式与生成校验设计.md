# 控制文件格式与生成校验设计

> 设计候选v0.1；依据SRS v1.0 FR-01/02/05/07、SR-01—10、C-04—11。这里定义候选格式和算法，不是已运行的生成器或已生效规则。

## 1. 输入、输出及唯一规则来源

首版候选采用UTF-8 JSON需求包和控制包，选择JSON便于确定性解析和版本差异；任务书并未强制JSON。可由表单填入结构化需求再序列化，不承诺理解任意自然语言。输入包含字段/模板、护栏条件与拒绝结果、编码规范和质量门禁，禁止管理上传临床正文作为生成原料。

控制文件目录仅保留一个完整候选包作为运行内容候选，含安全红线、编码规范、质量门禁三部分及授权、模板与分工结构；不在不同文件复制两套相互竞争的安全规则。演示输入与人工拟定输出对照分别留档。当前样例明确无审批、无启用，不声称生成器已成功运行。

包最小信封：格式版本、包版本、输入引用/版本、SRS基线、门店作用域、必需三部分、模板定义、权限定义、来源/差异、校验结果引用。内容摘要用于审批绑定，不是用临床正文哈希替代脱敏。可信提交身份从会话取得；样例中账号/审批/启用为空，不伪造管理签名。

## 2. 控制内容的解释边界

| 内容 | 候选表达 | 约束 |
| --- | --- | --- |
| 安全红线 | SR编号、适用操作、允许的事实选择器、条件、拒绝结果与事件分类、来源 | 系统安全底线不可由门店候选放宽；不新增药理剂量/禁忌数值 |
| 授权 | 稳定权限键、角色、门店与归属谓词、字段投影、审计类别 | 未声明即拒绝；只检查角色不够；前台/管理不配置临床全文 |
| 字段/模板 | 字段名、业务类型、必填、角色投影、模板版本、历史解释口径 | 处方按“无药可空、有药成组必有”，不新增临床正确性判断；旧病历引用不变 |
| 编码规范 | 统一授权入口、参数化查询、凭据安全、显式事务/审计、只追加与禁止危险解释器 | 控制文件不能含可执行Python/SQL；不允许eval任意表达式 |
| 质量门禁 | 题定覆盖、错误码/负向场景、漏挂权限阻断、规模/负载/恢复/维护性证据引用 | 配置的是必须验证的条件，不能把目标数字当已测结果 |
| 人机分工 | 工作项/阶段、计划维度、实际依据类型及复核要求 | 实际来源不足则不可比较；管理只读元数据，不因引用取得临床内容 |

规则条件采用受限事实与操作符：present、eq、in、all、any以及经过登记的领域检查器。不能引用任意对象属性、函数或文件；未知字段/检查器、类型不匹配、循环引用、重复ID冲突均生成失败。领域检查器对应基线约束，如相同接诊归属、只追加、采纳责任、模板必填、审计和批准内容绑定，不把“任意脚本”当扩展能力。

## 3. 生成校验过程与复杂度

```text
generate_candidate(trusted_actor, demand):
  require authorized(trusted_actor, governance.candidate.generate, demand.store_scope)
  parse strictly; reject invalid structure/unknown executable content
  require safety_redlines, coding_standards, quality_gates are present
  validate template fields, types, references, scopes and source identifiers
  compare with immutable SRS safety floor; reject any weaker/contradictory policy
  reject cyclic references and conflicting duplicate identifiers
  normalize deterministic ordering; compute candidate content digest
  persist input reference, candidate, differences and actual submit metadata
  return candidate + validation report; never activate here
```

设输入长度L、条目数N、引用边E、字段数F，解析/字典化和必需项检查O(L＋N＋F)，引用循环检测O(N＋E)，冲突比较使用规范化键后O(N＋F)，稳定排序至多O(N log N)。空间O(L＋N＋E＋F)。这些是候选算法分析，不是已实测耗时或最终代码复杂度。

编译失败只产生候选校验报告/治理事件，不生成“临床运行护栏命中”告警。缺部分、引用不存在、越店作用域或试图给管理全文均明确失败，不能偷偷补默认文件并当成输入完整。内部安全底线是校验依据，不能作为掩盖必需输入缺失的替代输入。

### 3.1 不可削弱的机械判据

编译器内的只读FloorSpec独立于管理输入，按SRS版本登记：SR-01—10各自的固定checker、适用phase集合、失败类别及必需义务；允许的角色最大行范围/字段投影、服务端操作模式、三必需部分、必填诊断和成组用药、真实采纳/审计/人工启用、题定质量数字。候选必须包含每条底线，并逐项比较这些结构约束；不能只读候选自称的`may_weaken=false`。phase删除、checker换成更弱检查、故障改成允许、管理投影增加正文、行谓词改宽、门禁阈值放宽均明确拒绝并报差异路径。

权限谓词和投影按登记标识编译，不求解任意表达式等价性；候选引用02的F/D/M/MA/MG及白名单，未知或越界定义失败。FloorSpec/SRS既定最低必需字段不可删除/改可选；非底线扩展字段可在新版本经审批增删变更，旧记录仍按原模板解释。扩展字段和规则必须使用已注册类型/检查器，新增检查器由代码模块扩展并接受同一安全底线及回归。质量目标比较按阈值方向执行（覆盖率等下限不能降低，P95等上限不能放宽），题定数据规模/并发/时长不得缩小；涉及正式统计口径的未决项不能用null表示已通过。

底线检查器按固定操作/阶段无条件调度，不能被候选的额外条件包裹成可绕过的分支。附加条件节点限定为`{op:present,fact:已登记名}`、`{op:eq,fact:已登记名,value:同类型标量}`、`{op:in,fact:已登记名,values:同类型标量数组}`以及`{op:all或any,args:非空节点数组}`；拒绝多余键、错类型、未知事实与循环引用。事实只由对应应用服务在规定阶段提供，不接受客户端自报授权/保存成功。SR-06写前只检查授权/范围/审计设施前提，实际审计持久成功必须由提交结果验证；无副作用规则引擎不提前声称未来commit已成功。每个checker的具体事实字段类型、资源边界和前后阶段契约属于编译实现前必须固化的登记，不是本轮已运行能力。

当前JSON使用文档投影引用，字段机器模式及FloorSpec尚未编译/实现，因此只作为人工拟定的完整内容候选，不能加载为运行配置。设计确认后必须把投影字段类型、允许事实选择器及上述逐项比对固化，并用“删phase、改checker、同角色放宽字段”等负向样本证明生成失败。本轮JSON结构检查不证明该编译器存在。

## 4. 版本、审批与启用

需求输入、候选、批准和启用是四个独立对象。候选内容保存后不可原位改成另一个内容；修改产生新版本和新摘要。真实本店管理审批时绑定包ID/版本/摘要并填理由，批准不立即切换。手动启用在事务中再次校验范围、结构、安全底线、批准绑定和当前指针，成功后原子切换所属门店的生效指针并留痕。

不要求两个不同管理账号，基线未设置双人审批。未初始化/无有效生效包时所有依赖该包的病历变更拒绝，不回退成允许。初始化演示也要有真实管理操作记录，不能把当前JSON样例的null字段补成虚构已批准历史。

旧病历依旧引用其原模板；当前权限和适用生效护栏仍按本次操作检查。启用与临床提交使用明确的版本绑定/并发检查，不能检查后任意切换规则再无条件提交。缓存按门店/版本读取，失去权威版本不能从陈旧缓存猜测放行。

## 5. 运行判定与告警分类

```text
evaluate_medical_change(context, operation, proposed_change, pinned_policy):
  check server-owned encounter state and expected record version
  check the record's referenced template and applicable active policy
  classify input syntax errors separately from evaluated runtime guard hits
  evaluate declared rules; collect hits by attempt + rule + field
  if confirmed runtime guard hit: reject medical mutation; persist hit/alert/outbox
  if missing policy or necessary persistence failed: reject and report real fault
  otherwise: allow application service to commit mutation + corresponding audit
```

模板必填缺失如果触发已启用运行护栏，仍记录命中，不被前置普通输入错误吞掉；认证拒绝、普通未构成护栏命中的格式错误与编译失败分别分类。固定R条检查器每条至多检查F个事实时为O(RF)；如果额外条件有G个节点、集合成员/变长值比较工作量I，整体朴素上界写作O(RF＋G＋I)，不能把任意嵌套和比较隐藏为常数。输入长度L已包括全部条件/字面量，生成分析中的N表示需排序的全部登记条目，表达式遍历计入L。按操作和字段预分组减少实际集合，不得漏题定红线；数据库、审计和网络成本另计。规则通过只表示可进入业务提交，不表示已保存。

## 6. 首批验证样例

| 样例 | 应观察结果 |
| --- | --- |
| 完整合法字段/三部分/来源 | 形成候选和差异报告，状态仍待人工审批 |
| 删除质量门禁、采纳红线或模板引用 | 定位缺项失败，无可启用候选 |
| 允许管理读全文、医生跨店或建议直接写入 | 定位冲突SR条款并失败，当前生效包不变 |
| 候选获批后改内容、跨店启用、失效批准 | 拒绝启用，不复用旧批准 |
| 新模板启用后读取旧记录 | 按旧引用解释；当前授权/适用护栏仍生效 |
| 队列失效、相同请求重试、新独立提交 | 本地待发不丢；同次不增；新提交命中按C-10分别留痕 |
| 同轮两条不同规则命中同一字段 | 按attempt＋rule_id＋rule_version＋field分别留两条命中；不因共用包版本误合并 |

真实生成、负向门禁和维护性试验在设计确认后实现并保留原始输出。本轮仅检查样例JSON语法和结构对应，不把它记成生成器测试通过。
