# 接诊归属与读取权限实现

> 2026-10-22。SRS v1.0不变；承接UC01及UC02.1、C07/C11。阶段1接诊/读取切片已落地，正式诊疗写入和临床运行护栏仍待下一批。

## 数据与不变量

新增05/clinic及正式迁移。PetIdentity仅登记UUID/门店，不含跨次共享资料；known引用只能核验本店给定编号是否可关联，不搜索宠物、不返回历史。Encounter按次保留宠物编号、种类/称呼/主诉、实际前台、同店接诊医生、门店、创建时间与原接待模板。归属在接口层不可改写；相同宠物的新接诊是独立对象，权限独立。

ReceptionRevision保存初版及每次普通资料更正，带实际账号/时间/理由；更正只允许species/complaint/pet_name，须匹配original_version_ref。误建单保留记录、标记账号/时间/理由，可读和纠正已有接待资料，未提供删除、解除标记或改派。可选重建引用只链接本店该前台自己的另一接诊；不因引用取得其他资料。

ClinicalRecord/ClinicalRevision当前仅支持已有诊断/检查及其版本读取，正式写入接口尚未开放。病历持有原候选/模板引用；读取核原包摘要、批准和启用历史，不换成当前最新版。没有正式病历时返回clinical=null，页面明确“尚无正式病历”；不伪造空诊断、处方、建议或临床告警结果。单元测试中的正式病历是明确合成夹具，应用库演示未用夹具创建正式病历。

## 入口和投影

| 接口 | 权限/模式 | 本批具体输入与结果 |
| --- | --- | --- |
| POST /api/encounters | encounter.create/create | pet_identity_choice=new/known、pet_ref UUID、species、complaint、doctor_ref；pet_name可选，template_ref若给出须为本店当前生效候选。返回R-RECEPTION |
| GET /api/encounters/create-options/doctors | encounter.create/doctor_options | 无业务参数；仅本店有效医生编号/账号显示名 |
| POST /api/encounters/create-options/pet-reference-check | encounter.create/verify_pet_ref | 仅pet_ref；只回编号/associable |
| GET /api/receptions、/{UUID} | encounter.read/list或detail | 只该前台本店接待数据；不加载临床实体、不返回诊断等嵌套字段 |
| POST /api/encounters/{UUID}/corrections | encounter.correct | 可改字段、original_version_ref、reason；保留原值和责任历史 |
| POST /api/encounters/{UUID}/misregistration | encounter.mark_error | reason；可选rebuilt_encounter_ref，目标仍独立核权 |
| GET /api/clinical/encounters、/{UUID} | clinical.read/list或detail | 只当前医生本店负责记录；只读关联接待资料及已实现临床字段/版本 |
| GET /api/audit?record_ref=…&operator_ref=… | audit.metadata.read | 管理只查本店既有脱敏元数据，不提供正文跳转；原最近100项显示边界保留 |

列表业务筛选只接受encounter_ref/record_ref/time_range；record_ref仅医生使用。time_range为带时区的from/to，起点包含、终点不含；本期不混用显式引用与时间/分页条件，混用明确422。page为传输分页元数据，固定每页50，稳定按创建时间/编号倒序，返回page/page_size/total。前台、医生均先在数据库按店/账号过滤，不全表取回再过滤。

上述具体路由补齐既有权限目标，未修改权限底线。接待接口不接收诊断、归属、服务端时间或账号；辅助模式不接受任意查询条件。新临床字段、用药及建议聚合将在各自实现阶段显式序列化，不把semantic_group当实体通配许可。

## 事务、读取和拒绝审计

沿用服务端身份、会话、CSRF及统一入口。创建/更正/标记要求Idempotency-Key UUID；同账号/权限/操作仅一笔结果，换目标/内容冲突；重放前再次核当前身份、门店与接待归属。接待写入、历史、审计、逐目标索引和操作结果同事务，故障全部回滚。

接待写按账号→（创建时策略指针）→接诊→历史/审计执行；创建医生必须当前同店有效，当前模板须已批准启用。更正使用原引用，不强迫升级。读取在事务中锁定本页接诊，批量预取被授权关系，避免字段和版本跨时点拼接；前台不预取临床关系。每页先完成全部必需审计及逐目标索引再返回JSON。51条跨页用例核集合和索引，并限制页读取查询次数，避免逐记录查询扩张；这不是正式性能成绩。

AuditTarget关联读取/拒绝事件到接诊与已有病历UUID，仅存不含正文的引用。实际读取、授权拒绝和设施故障不同；拒绝在失败事务外留存。可信账号跨店临床拒绝按C11仅请求账号店可见，目标店无新增可见权；无身份/未知目标不随意归店。审计投影严格保持R-AUDIT九字段，普通理由/诊断/主诉不进管理输出。

错误码沿用AUTH_REQUIRED=401，PERMISSION_DENIED/TARGET_UNAVAILABLE/DOCTOR_UNAVAILABLE/PET_UNAVAILABLE=403，输入/引用/模板不匹配=422，幂等/旧版本/重复标记/编号冲突=409，原模板/病历不可解释或持久化不明=503；病历读取审计失败不返回正文。队列/临床命中处理不在本批假装实现。
