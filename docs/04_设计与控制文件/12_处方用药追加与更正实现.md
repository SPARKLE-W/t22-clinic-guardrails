# 处方用药追加与更正实现

2026-10-23。需求v1.0不变，承接FR04/07、SR02/03和既有W-MEDICATION、R-WRITE-RESULT、R-CLINICAL。药品、用量、单位为非空文本，不添加药理阈值。

POST `/api/clinical/encounters/{UUID}/medications` 固定append；同路径`/corrections`固定correct；权限均为medication.record。账号、门店和真实父接诊使用D判定。correct引用必须实际属于该病历，不能用其他接诊或跨店子项替换父关联。无正式病历不能写入。误建仅允许对已有项关联纠错，不允许追加独立治疗。

MedicationEntry每次只新增，保存原项外键、实际医生/时间/理由及校验引用；没有更新、删除入口。更正可引用原项或既有更正，形成完整可追溯链，读取不裁去旧项、不擅自将某分支宣称唯一有效处方。诊断版本不因追加用药而虚增。临床读取显式投影medication_chain并批量预取；前台和管理不读取该链。写入响应只含引用/状态/真实责任元数据，获取正文另走受控读取审计。

复用账号→策略头→接诊锁序。原病历模板解释字段、当前已批准启用规则执行校验。SR02检查用药三字段齐全，SR03检查更正原项和理由；不合格提交持久命中、告警、待发、拒绝审计及幂等结果，病历不变。格式错误、子项越权和设施故障不冒充临床命中。通过时新增项、校验、审计、幂等结果同事务。持久化失败全部回滚，不虚报成功。

同键同内容返回同一引用，换目标/模式/内容冲突；每次重放重新授权。并发同键只生成一条，多个独立更正均是新增历史，不覆盖原项。当前不增加单一“最终处方”业务状态、撤销/删除或特殊覆盖入口。

医生页展示原项和每次关联更正，提供追加/更正、原项选择、三字段及理由录入。已标误建只保留已有项更正选项。实际规则命中保持医生工作台提示，MQ实际补发仍待后续；本批不宣称AI建议、人机分工、导出或正式性能验收已完成。
