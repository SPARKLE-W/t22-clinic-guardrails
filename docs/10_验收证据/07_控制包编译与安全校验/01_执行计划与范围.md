# 控制包编译与安全校验执行计划

> 2026-10-21。承接用户“先进行下一步吧”、SRS v1.0及04目录01/07；本批不继续压测，不修改需求，不启用真实门店控制包。

## 1. 本批出口

将已有人工作为设计候选的JSON细化为可执行机器契约，完成纯控制包编译器及命令行：严格解析、三必需部分、独立安全底线、20权限键及字段投影、模板、注册检查器/事实/阶段、受限条件、引用/类型、质量目标、防篡改摘要和可定位失败。合法定义产出可复现且未提交/未审批/未启用的候选；缺项、冲突、削弱或未知内容失败，不输出可用候选。

本批是正式实现的首个控制编译子批次。核心不依赖Web框架，因此不把B预研选择扩大为最终部署批准。账号授权、候选持久化、真实管理审批/手动启用的数据库事务、前端及临床运行调度后续接入；本批静态编译成功不表示这些功能已完成，不伪造真实账号签名或成绩。

## 2. 文件归位与唯一来源

- 当前实现放`05_系统代码/vetcontrols`，测试与便携示例在同目录tests/examples；不从第06阶段探针复制出“正式系统”。
- 机器契约细化放04目录08。首轮v0.1人工作为输入/预期输出保持原样，不假装旧样例已经由程序生成。
- 本批来源核对、测试红绿、实际CLI输入输出、审查及指纹集中本阶段。编译得到的候选仅是演示证据，没有活动指针。
- SRS v1.0、原任务书、旧快照及08/12/16历史检查不修改；没有本批需求变更或自动最终选型。

## 3. 执行顺序与检查

1. 细化机器输入/输出、FloorSpec和权限/类型登记；核对10条SR及既定20目标。检查：来源和不可削弱项逐一对应，不新增主人端/临床药理阈值。
2. 先写最小失败测试并实际运行，确认功能未实现而失败；再实现解析、编译和约束。检查：合法、删项、删phase/改checker、投影/行范围放宽、错类型、循环引用、门禁放宽均有正负样本。
3. 实跑CLI完整/缺项/冲突，保存原始报告、退出码和内容摘要。检查：失败没有候选、成功仍未审批；输入/候选摘要可复算，输入顺序不改变规范化内容。
4. 既有三代理各负责来源、角色与工程的限定工作，末尾一次综合审查；只对实质修正定点复跑。检查：不把AI审查当真人审批、不把静态配置目标当实测结果。
5. 核需规指纹、代码/JSON/链接及回归；更新导航、设计与AI过程。检查：无服务被启用、正式性能仍未验收，下一批审批接入的前置条件明确。

## 4. 工程取舍

选择结构化JSON及确定性编译，沿用04设计；本批不调用模型理解自由文本，不增加脚本执行/任意检查器插件。先让固定安全底线和已登记类型可验证；后续扩展通过明确登记及同一回归承接。较严格的首版输入契约属于技术实现选择，不新增运行角色、导出权限或医疗规则；未表达的字段/规则明确报错，不偷偷补默认值。

使用既有设计梳理、测试先行和执行计划技能。用户已要求按现有流程进入下一步，本批为可逆实现与可审查产物；真实治理审批仍必须由后续系统内管理账号操作，不由本次开发指令代替。
