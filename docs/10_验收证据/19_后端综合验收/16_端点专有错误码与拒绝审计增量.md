> 2026-10-24。本批以真实 Django HTTP 入口、独立 `t22_app_test` 合成库检查端点专有拒绝；只证明下表路径，不把它外推成所有端点和所有错误码已覆盖。共享 18730 及应用库未改写。

## 被验证的负向路径

| 接口与条件 | HTTP／`error.code` | 同步核对 |
| --- | --- | --- |
| 管理跨店生成规则 | 403 `SCOPE_DENIED` | A店账号拒绝审计归A店；无需求包、候选和操作记录 |
| 未批准草案启用；过期代数启用 | 409 `APPROVAL_REQUIRED`；409 `POLICY_VERSION_CONFLICT` | 拒绝审计原因一致；原启用头和启用历史不变 |
| 前台关联B店宠物；指定非当前模板 | 403 `PET_UNAVAILABLE`；422 `INVALID_TEMPLATE` | A店拒绝审计；无部分接诊及接待版本 |
| 前台以旧版本更正；重复标误建 | 409 `STATE_OR_VERSION_CONFLICT`；409 `STATE_CONFLICT` | 拒绝审计；现有更正和误建状态保留，不追加错误版本 |
| 管理对不可比较项强行复核；换证据；掩盖实际差异 | 409 `EVIDENCE_INSUFFICIENT`、`EVIDENCE_VERSION_CONFLICT`、`REVIEW_CONCLUSION_CONFLICT` | 管理拒绝审计；未创建人工复核记录 |
| 医生显式导出混入非归属病历 | 403 `TARGET_UNAVAILABLE` | 整批拒绝、不生成CSV或导出申请；审计关联已知目标且归请求门店 |
| 当前病历版本缺诊断时读取与导出 | 503 `RECORD_UNAVAILABLE` | 不释放临床正文／CSV；拒绝审计归医生门店；不生成导出申请 |

新增HTTP规则用例首先复现真实缺口：跨店生成已返回 `SCOPE_DENIED`，但治理服务在抛错后的审计未设置门店，A店管理无法按已确认的请求账号所属门店查看。修复仅在治理拒绝审计缺少已核实门店时回退到实际账号所属门店，未改变授权判定、规则状态或临床可见范围。修复后这批定点检查通过。

完整 `manage.py test vetcontrols governance clinic tests --noinput -v 1` 在本机 MySQL／RabbitMQ、独立测试库运行：**193项，0失败，0跳过**。同一测试集的[覆盖率运行](%E5%8E%9F%E5%A7%8B%E7%BB%93%E6%9E%9C/coverage_full_03.txt)亦通过，生产Python语句覆盖率[89%（2183/2462）](%E5%8E%9F%E5%A7%8B%E7%BB%93%E6%9E%9C/coverage_report_03.txt)。故意注入的导出生成异常会输出一段合成 `KeyError` 日志，测试断言其返回受控503，不属于本轮失败。对应测试源码及Git提交可复跑；本批没有重新执行360在途正式负载，因此AC-06仍未通过。

## 尚未闭合的范围

各端点仍需对照需规中的全部负向条件，尤其告警处理、用药与建议状态、规则事实不可用、分工登记查询参数及三类导出筛选，逐一标记实际HTTP码、审计和事务结果。本批不把若干高风险用例通过改写成AC-08整体通过；真实AI规则／权限代码幻觉及人工修改数量也仍按个人材料单独核实。
