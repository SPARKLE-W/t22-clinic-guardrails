## 1. 冻结目标与边界

**课堂主线：** 按[AC-06课程口径v1.1](22_AC06%E8%AF%BE%E7%A8%8B%E5%8F%A3%E5%BE%84%E4%B8%8E%E5%AE%9E%E6%96%BD%E8%AE%A1%E5%88%92.md)，使用5店、6000只宠物、约20000份病历，360个独立登录会话持续活跃；预热60秒、正式600秒，每个会话操作后按固定种子等待15—25秒；每分钟至少800个成功请求、授权业务请求零失败、各类别完整响应P95≤280ms，三类导出分别报告并校验完整响应。报告只围绕这一课程主线组织。

**内部拓展：** TBR-05 v1.0保持原冻结值：360个业务请求持续在途、预热300秒、正式600秒、每分钟≥800次、七类分别P95≤280ms、零失败；导出范围分布和其他条件按[协议](01_%E6%AD%A3%E5%BC%8F%E8%B4%9F%E8%BD%BD%E6%B5%8B%E9%87%8F%E5%8D%8F%E8%AE%AE_v1.0.md)。该拓展结果单独存档，不替代课堂主线，也不写入课堂报告。

本轮使用已采购的 Windows Server 2022 ECS 和本机独立压测客户端，先测当前单机分层应用实际能力。先做证据归因，再决定是否切换 Linux、拆分客户端/服务端进程或调整线程/连接池；不把扩规格本身当作解决方案。异步导出、导出范围或流量配比等契约变化会改变冻结需求，未经本人及课程口径确认不实施。

## 3. 每轮共同控制

- 每次记录源码 commit、实例与客户端配置、OS/运行时/数据库/队列版本、数据夹具摘要、变更项、命令、原始输出位置和哈希。
- 一次只改一个瓶颈类别；改动前后使用相同合成数据与负载；测试和性能脚本不纳入有效产品代码行数。
- 数据库不开放公网访问；SSH仅允许已核准的单个 IPv4 `/32`；密钥和应用/数据库凭据不进 Git、聊天记录或测试报告。
- 正式请求从发起到完整响应体接收；所有错误、超时、断连、摘要不符和服务端错误计失败。保留失败样本与慢请求。
- 本地既有完整回归是代码正确性基线；云端性能窗口不能替代本机测试，反之亦然。

**容量估算（仅供下一步选型，不是验收结果）：** B1正式混合轮平均响应体约20.4KB；若以360个请求持续在途、平均响应时间接近280ms估算，约需1,286次/秒，对应约210Mbps纯响应载荷，尚未计协议开销。该估算假设请求闭环、无思考时间，只用于识别公网100Mbps峰值可能成为额外上限，不构成新增验收条款。B1客户端主机网卡接收采样P95约86.9Mbps、峰值约113.1Mbps，为聚合网卡观测，不能单独证明ECS公网出口已限速。B1大体量临床导出（1000–4000行档）响应体P95约2.42MB，100Mbps理想传输时间约194ms，接近整个280ms目标；服务端生成耗时尚未计入。B1同时存在CPU饱和与临床导出应用阶段高耗时，故仅升级公网带宽或仅升级CPU都不足以证明可达标。优先在现有代码上降低查询/导出 CPU 与 SQL 成本，并采用同VPC独立压测客户端减少公网路径混杂；若需单机硬件候选，48 vCPU/192GiB比32 vCPU更接近当前约6倍吞吐差距的线性估算，但这只是待验证候选，变更规格仍需用户决定。

**历史瓶颈事实：** 第30/31号记录中，360持续在途的短轮七类P95约数秒至十余秒；16×23优于8×45但无达标证据。连接复用60秒消除了TIME_WAIT/端口耗尽相关失败，数据库行锁采样为0；旧轮应用CPU峰值/ P95为100%，可用内存充足，磁盘写压力偏高但缺乏与失败同窗的读写IOPS证据。round36在正式窗口发生大量连接重置、结果无效。当前PR #95只优化一次病历查询，不能假设解决CPU/队列问题；本轮须用当前源码重新定位，而不是重复旧线程矩阵或预设根因。

## 5. 目标跟踪

本轮执行目标为**按冻结TBR-05严格口径达标**，完成条件是同一最终提交和固定环境在360持续在途及300+600秒正式窗口中同时满足逐分钟吞吐、各请求类别P95、零授权失败与导出完整性要求，并保留可复核原始证据。任何短轮、历史版本或本地服务层测量只作为诊断，不能代替正式通过。已完成B0/B1缓存池对照和B2隧道对照；缓存池提升显著改善SQL阶段但未让HTTP响应接近280ms，增加SSH连接数亦未显示改善。测得8 vCPU服务器CPU满载，B1出口/客户端聚合接收接近100Mbps峰值，且大导出本身占用较多响应时间；尚不能将性能瓶颈归结为单一因素。下一步按服务端CPU占用、审计写入、请求阶段计时、SQL digest和临床导出序列化逐项归因及优化，优先使用当前ECS做短诊断；待代码候选可复现改善后，再用同VPC负载客户端和更高CPU候选做分阶段验证，不擅自升级或新租云资源。
