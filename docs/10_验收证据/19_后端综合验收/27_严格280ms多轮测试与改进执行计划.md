## 1. 冻结目标与边界

**课堂主线：** 按[AC-06课程口径v1.1](22_AC06%E8%AF%BE%E7%A8%8B%E5%8F%A3%E5%BE%84%E4%B8%8E%E5%AE%9E%E6%96%BD%E8%AE%A1%E5%88%92.md)，使用5店、6000只宠物、约20000份病历，360个独立登录会话持续活跃；预热60秒、正式600秒，每个会话操作后按固定种子等待15—25秒；每分钟至少800个成功请求、授权业务请求零失败、各类别完整响应P95≤280ms，三类导出分别报告并校验完整响应。报告只围绕这一课程主线组织。

**内部拓展：** TBR-05 v1.0保持原冻结值：360个业务请求持续在途、预热300秒、正式600秒、每分钟≥800次、七类分别P95≤280ms、零失败；导出范围分布和其他条件按[协议](01_%E6%AD%A3%E5%BC%8F%E8%B4%9F%E8%BD%BD%E6%B5%8B%E9%87%8F%E5%8D%8F%E8%AE%AE_v1.0.md)。该拓展结果单独存档，不替代课堂主线，也不写入课堂报告。

本轮使用已采购的 Windows Server 2022 ECS 和本机独立压测客户端，先测当前单机分层应用实际能力。先做证据归因，再决定是否切换 Linux、拆分客户端/服务端进程或调整线程/连接池；不把扩规格本身当作解决方案。异步导出、导出范围或流量配比等契约变化会改变冻结需求，未经本人及课程口径确认不实施。

## 2. 多轮执行

| 轮次 | 工作 | 量测与判定 | 进入下一轮条件 |
| --- | --- | --- | --- |
| 0：环境可复现 | 固定 Git 提交；只读核对 Windows、磁盘、MySQL 安装/数据目录；完成隔离 MySQL 初始化和最小权限账号；安装 RabbitMQ；部署锁定依赖与源码；记录环境/配置摘要。 | 服务健康、迁移成功、合成数据生成计数符合协议、队列及工作进程状态可观测。数据库只监听本机/私网；凭据放仓库外。 | 仅在空的、明确为验收用途的数据目录上初始化；服务健康及数据可重建后进入基线。Configurator 不在非交互 SSH 会话中重跑，改用无桌面的受支持配置步骤或交互桌面。 |
| 1：单请求分段基线 | 不改业务代码；用同一代码、独立合成库和正式夹具，测 1 并发代表性查询、护栏、接诊、病历写入和三类导出，包含小/中/大导出。 | 完整响应时延、SQL/锁/审计/CSV各阶段耗时、返回字节及摘要、CPU/内存/磁盘/网络；校验每类权限与结果。 | 找出各类主要耗时来源。若单请求本身超280ms，先定点优化该类别；否则进入并发阶梯。 |
| 2：并发阶梯基线 | 按 1、10、30、90、180、360 个持续在途请求逐级短测，每级 60 秒；固定请求种子与配比，压测客户端和应用服务器分机运行。 | 每级七类 P50/P95/P99/最大值、失败和吞吐；实际在途、入口等待、活跃线程、DB连接与锁等待、导出分层、客户端/服务端资源。 | 找到时延拐点及首要瓶颈；确认压力端未饱和。阶梯探针仅用于诊断，不记作正式验收。 |
| 3：运行时与连接改进 | 仅当第2轮显示入口排队或连接耗尽时，调整 Waitress/进程与线程数、连接复用和 DB 连接上限；每次只改一组参数并保留前后提交/配置。 | 重跑受影响阶梯；比较入口排队、连接等待、资源和各类延迟，确保数据库连接未耗尽、内存未交换/耗尽。 | 阶梯吞吐提升且零回归才保留；若 DB 先饱和则停止加线程，转向数据库或锁诊断。 |
| 4：事务锁与查询改进 | 若写请求/护栏锁等待占主导，围绕 `Account`、`PolicyHead`、`Encounter` 临界区做最小改造；若查询 SQL 占主导，基于慢查询和执行计划优化索引/预取。 | 对照查询与写路径分段时间；回归撤权生效、规则版本一致、病历事务、幂等、并发冲突、审计失败回滚及租户隔离。 | 正确性回归全部通过，锁等待下降且目标类别分位改善。不能删除权限校验或同步必要审计换性能。 |
| 5：导出专项改进 | 若导出主导尾延迟，按 1/20、50/200、1000/4000 规模分别测 SQL、审计目标写入、CSV、摘要与传输；先评估批量审计、索引、查询和生成成本。 | 完整响应计时；核对授权范围、行数、长度、字节计数、摘要和审计完整性。大导出失败、超时或 OOM全部保留。 | 原协议范围下改善且安全回归通过才保留。若同步大导出仍超标，只提交证据与契约选项，等待人工确认；不得擅自缩范围或改配比。 |
| 6：综合短测 | 合入已验证的独立改进，锁定最终候选源码、迁移、夹具、配置与种子；先跑 60 秒 360 在途短测。 | 检查真实在途达到目标、压力端不饱和、服务无积压/错误、各类 P95 与资源可接受。 | 短测无异常才进入正式窗口；短测不能写成通过。 |
| 7：严格正式复测 | 完全按TBR-05原协议：300秒预热＋连续600秒正式窗口；运行期间冻结代码、数据生成、索引和配置。 | 每分钟吞吐；360持续在途证据；七类P50/P95/P99/最大值/样本数；零失败；完整响应体及导出摘要；CPU、内存、磁盘、网络、连接、锁和原始请求数据。 | 所有目标同时满足才记严格通过。任一不满足则报告实际差距，基于证据开下一轮，不剔除失败或慢样本。 |

## 3. 每轮共同控制

- 每次记录源码 commit、实例与客户端配置、OS/运行时/数据库/队列版本、数据夹具摘要、变更项、命令、原始输出位置和哈希。
- 一次只改一个瓶颈类别；改动前后使用相同合成数据与负载；测试和性能脚本不纳入有效产品代码行数。
- 数据库不开放公网访问；SSH仅允许已核准的单个 IPv4 `/32`；密钥和应用/数据库凭据不进 Git、聊天记录或测试报告。
- 正式请求从发起到完整响应体接收；所有错误、超时、断连、摘要不符和服务端错误计失败。保留失败样本与慢请求。
- 本地既有完整回归是代码正确性基线；云端性能窗口不能替代本机测试，反之亦然。
