# TBR-05 正式负载第二轮实测（仍未达标）

2026-10-24，按已冻结的《01_正式负载测量协议_v1.0》再次执行完整 300 秒预热＋600 秒正式窗口。相对[首轮](04_%E6%AD%A3%E5%BC%8F%E8%B4%9F%E8%BD%BD%E9%A6%96%E8%BD%AE%E5%AE%9E%E6%B5%8B.md)，本轮只在测试前修改病历读取/导出的当前账号锁及读路径；运行窗口内未改源码、索引、配比或服务配置。**360 在途、逐分钟至少 800 次和正式窗口零失败达到口径；七类请求 P95 均未达到 280 ms，AC-06 仍不通过。**

## 环境与可复核范围

- 源码提交 `57b32a30c2e7f560f9e67ca5bf0064082159461f`，独立 `feat/formal-load` 分支；独立测试库 `t22_perf_20261024_r2_test`、Web `127.0.0.1:18830`、RabbitMQ 队列 `t22.app.formal.20261024.r4`。没有使用共享 18730 或其应用库。
- 与首轮相同固定种子 `20261024`：5 店、6000 宠物、20000 接诊/病历及相同请求类型配比。预置历史告警中的投递状态仍含明确标注的**合成回执**，只为避免夹具积压，不能当作实际 MQ 投递验收。Web 为 Waitress 120 线程、MySQL 连接上限 151；负载和服务同在本机 Windows 11。
- 客户端从发起请求计时至完整响应体接收。三类 CSV 另检查 `Content-Length`、`X-Byte-Count`、实际字节数和 SHA-256。正式窗口发起 16705 次，所有这些请求最终成功；其中 16345 次在窗口内完成，其余在窗口后排空。
- 启动头约 0.1—0.43 秒发出的 70 次请求在**预热期**出现 `ConnectionError`，结束时间约 2.5 秒；它们不属于正式窗口，也不能被写成“整次运行零失败”。正式窗口单独统计为 0 失败。

正式窗口各分钟完成数依次为 **1588、1677、1807、1497、1679、1398、1458、1589、1825、1827**，均无失败且高于 800。0.1 秒在途采样最小 359、中位数/P95/最大值均 360；实际配比为查询 29.99%、护栏 15.00%、接诊 15.00%、写入 20.00%、三类导出合计 20.02%。正式窗口全部 3344 次 CSV 导出通过长度和 SHA-256 校验。病历 CSV 1—20、50—200、1000—4000 份的 P95 分别约 23819、24734、34472 ms；命中明细相应约 26354、25396、33613 ms，完整体计时没有因小文件而达到 280 ms。

主机 CPU 采样峰值 70.1%，内存占用峰值 79.1%；Web RSS 峰值 590471168 字节，MySQL RSS 峰值 697733120 字节。Waitress 日志出现 25135 条队列深度告警，记录最大深度 242；这表明服务入口持续排队，但**不能单靠队列日志判定数据库锁、CPU、线程数各自的贡献**。首轮病历查询 P95 31379 ms，本轮 25001 ms；其他类别有升有降，整体仍在十秒量级。短探针中解除读锁的改善不能外推为正式达标。

正式测量结束后，曾复用**已被测量请求改写的同一夹具库**做30秒无预热诊断探针；2042次请求中768次失败，包含414次旧版本/已终结业务状态冲突和354次连接异常。由于夹具已变、没有预热且不是独立正式窗口，这批数据**不能加入或覆盖上表，也不能作为AC-06复测**；原始诊断文件另存仓库外 `diag-360-r4-30s.*`。诊断期间两次只读 `SHOW FULL PROCESSLIST` 约见118—122条连接，主要处于 `statistics`（大量当前账号SELECT）和 `update`（大量审计/导出INSERT）状态；没有获得逐语句锁等待与CPU归因，后续优化须另建有效诊断夹具。

## 判定和后续

正式吞吐约 27.2 次/秒，稳定约 360 个请求在途，与十秒量级响应相符。若**平均**完整时延也接近 280 ms，固定 360 在途对应约 1286 次/秒的容量示意；P95 ≤ 280 ms 本身不能推出这一硬性吞吐下界。本轮远未达到 P95 目标。下一步需定点诊断 Waitress 排队、数据库语句及服务层成本，再决定是否值得做架构/运行时优化并完整重测。冻结口径及失败结论不因实现困难而改变；[原文口径与改进决策](21_AC06%E5%8E%9F%E6%96%87%E5%8F%A3%E5%BE%84%E4%B8%8E%E6%80%A7%E8%83%BD%E6%94%B9%E8%BF%9B%E5%86%B3%E7%AD%96.md)另行区分任务书和项目协议。
