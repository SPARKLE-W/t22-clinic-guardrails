# T22 最终整体验收与提交整理计划

> 2026-10-25。对象为 GitHub `main` 合并 PR #43 后的代码与文档。本轮由主代理执行，模拟教师、模拟学生和技术审查子代理只提供 AI 复核意见；他们不代表真实授课教师、课程本人或人工批准。原任务书与《作业提交注意事项》保持原样。

## 本轮目标

把前端、后端、数据/消息队列、四类课程交付物及其证据整理为**同一源码版本、可复查、可由本人最后审定**的候选提交包。成果说明按本人要求集中列出已实现的需求与已取得的目标；所有量化数字必须注明实测口径，不把 AI 审查当真人签字。

## 执行与通过条件

| 顺序 | 行动 | 可复查的出口 |
| --- | --- | --- |
| 1 | 从 T22 任务书、可信课堂汇总、群通知和《作业提交注意事项》列交付清单；教师、学生、技术三视角交叉审查。 | 三方意见、证据位置、主代理逐项处置；最终候选文件逐一对应四类交付要求。 |
| 2 | 核对当前 `main` 的三角色前后端主流程、权限/审计、控制文件、队列、导出、前端入口与测试记录。 | 当前源码上的系统检查、自动回归、前端检查及必要的隔离 HTTP 冒烟记录；复用已有真实浏览器和负载证据时标明版本与适用范围。 |
| 3 | 以 Markdown 为源修订面向提交的需求、设计、测试、AI 规格说明、个人报告和运行说明，并重生成 Word。 | Word 可打开且结构有效；源码、数字、图表、引用、封面状态及成果表述一致；不补造个人身份、真人工修改、幻觉或审批。 |
| 4 | 从当前版本选取代码、报告、AI 可执行规格与必要脱敏证据，生成逐文件清单与候选包。 | 候选包可重建、无账号口令/私密配置/数据库/他人原件；记录包及关键文件摘要。 |
| 5 | 走分支、PR 与 CI，核对最终文件及工作区，交本人逐项验收。 | PR 合并、CI 通过、候选包与合并提交对应；用户审定前不代填身份或宣称教师最终验收。 |

本轮收口以**真实证据支持的成果展示**为准。若课程专属 AI 留痕数量缺少可核实的真人证据，则在内部审查记录与本人验收清单标明，不用代理操作充数，也不把该项写成已经完成。
