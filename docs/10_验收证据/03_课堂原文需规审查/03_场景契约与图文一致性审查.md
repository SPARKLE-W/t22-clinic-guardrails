## 2. 五项发现与最小改进

### F-01 公共校验在正文存在，但未落实为用例间关系

**课堂依据：** L1提取段162—175，邻近01:00:41；L2 00:06:34、00:07:53、00:14:53—00:15:59。老师以共用必需步骤说明include，以条件发生的扩展说明extend，并要求检查用例间关系。课堂例子不能变成T22新增认证方式或业务。

**当前观察：** D§4.6、FR-07.5—07.7、FR-08以及§8已规定统一授权、模板/护栏及审计，但D§6.3图片和图源只有人—用例实线。公共行为没有被图表达，不能把“线条表示参与关系”当作公共校验关系已经画出。

**最小建议：** 从已经明确的义务提取内部共用行为，不增加业务用户或独立可操作入口。可将“核验当前身份与数据范围”“解释模板并校验本次临床变更”“记录适用访问/操作审计”分别表达为共用行为。具体适用关系按下表，不全挂给所有大组：

| 场景 | 应表达的必需公共行为 | 必须保留的限制 |
| --- | --- | --- |
| 受保护人工操作 | include身份与数据/操作范围核验 | 表达服务端每次核验，不等于要求每步重新输入密码，也不包含公开登录入口自身 |
| 读取病历、导出病历 | include本次访问/导出审计；身份范围校验仍必需 | 所需审计失败不返回病历字节；不能只在写入用例挂审计 |
| 正式病历写入、追加/更正、建议采纳入病历 | include本次模板/状态/生效护栏校验，并表达业务与相应审计一致完成 | 历史模板解释与当前授权分开；include线不代替同事务约束 |
| 不采纳建议 | include获准身份/病历范围和责任登记等已定必需行为 | 不因与采纳同属UC-04，就强行执行“采纳理由必填”或“写正式病历” |
| 队列补发内部场景UC-12 | 按现有事件/告警关联和幂等恢复表达 | 不挂“人工重新登录”，不造第四个业务用户 |

include箭头应由使用公共行为的基础用例指向被包含行为，标明`«include»`。对于条件性护栏告警，可由“登记命中告警”扩展指向“执行本次护栏校验”，标`«extend» [运行护栏命中]`并说明扩展点在命中判定后。**该关系的条件性是“不是每次都命中”，不是“命中后可以不告警”**。不能把告警处理或恢复补发都画成校验命中即必须完成；命中留存、医生处理、消息传输是不同结果。普通格式错误、身份拒绝、生成失败与临床护栏命中仍按D分类，不用extend图把所有失败混成临床告警。

### F-02 复合用例组需要对子目标分清触发边界，不能用include表示前后顺序

**课堂依据：** L1提取段218—225，邻近01:14:42/01:20:37；L2 00:14:03、00:21:24—00:23:16。图、清单和每个用例说明表共同表达目标及场景，不能只保留一个大功能名。

**当前观察：** D用例虽有十二组完整表，但UC-02合并查询与记录、UC-06合并审批与手动启用、UC-07合并统计与审计、UC-11合并登记与复核。它们有不同的输入、独立触发和成功结果。UC-04采纳与不采纳共享前置，但后续必需步骤不同。若直接在整个复合组挂include，会错误表示“查询必须写诊疗”“不采纳必须写病历”或“每次启用必须重新审批”。

**最小建议：** 保留UC-01—12作稳定追踪组；只给可独立触发的目标加子编号，或把不可独立触发的选择写成组内具名分支。审批与启用应有分别可观察的结果：已批准是启用前置，不能用“启用include审批”制造重复批准；查询病历与提交诊疗分开后，公共关系分别适配。登记与复核也分别说明输入和结果，FR-03仍是产品功能，不是开发代理分工。命中导出的医生明细与管理汇总可保留共同导出组，但必须保留不同主体、投影和数量语义。无需为数字硬拆成20个业务目标：本轮L1提取段217的“十几个/20个”属于当时案例讲解，不能从旧总结[218]移植成T22新增数量指标。

### F-03 主场景应给少量编号业务步骤，输入和输出分别可核对

**课堂依据：** L1提取段221—224，邻近01:14:42/01:20:37；L2 00:14:03明确要求“输入、输出、中间一步一步过程”；L5文件15—23行强调输入、输出及错误要完整。

**当前观察：** D§6.2已列角色、前置、输入/输出、主场景、异常、后置，不能说没有详细用例。但主场景仍多为一个分号串；异常常把权限、模板、重复和设施失败列在一起，没有把失败挂到业务步骤。读者需同时跳读§4/7/8才能判断“哪里失败、哪部分未提交、看到什么结果”。

**最小建议：** 每个子目标用少量编号步骤表达“谁提出什么→系统核验什么→成功保存/返回什么”，而不是代码执行细节。将“输入/输出”拆成明确的输入、成功输出、失败结果引用，字段清单仍引用C-06，不复制三套。临床提交可用以下骨架逐例裁剪：

1. 获准角色提交目标、操作、本次内容/引用版本及题定必需理由。
2. 系统核验当前身份、门店/归属和该操作的业务状态；失败转指定拒绝分支。
3. 按目标引用模板和适用已生效规则校验本次内容，保留校验依据；命中转护栏分支。
4. 通过后保存本次变更及相应审计；更正保留原项，采纳保留实际责任依据。
5. 持久结果确定后反馈成功引用与结果；结果未知转核对分支，不假报回滚。

读取、审批启用、导出及分工比较不能机械照套这份临床写入骨架。读取在所需审计完成前不返回正文；导出按C-08从授权集合到完整产物、审计、响应/接收状态展开；审批/启用输入是非临床候选内容；分工比较只使用同工作项阶段的脱敏元数据。这些是需求步骤，未指定服务类、数据库表、函数调用和锁顺序。

### F-04 失败分支要承接既定幂等、未知结果和告警计数，不能统称“异常即失败”

**课堂依据：** L1提取段219—224的多场景说明；L5接口段对连续点击提交及错误返回的讨论（文件20—23行，邻近00:00:00转写块）；L5 01:01:39—01:02:45要求分别检测需规及其与设计的一致性。T§5和D§8/C-10已把本题规则写得更具体，不从课堂例子新增重试实现。

**当前观察：** D§8.2和§7.6已明确重试、同标识异内容、断连未知、审计故障及C-10计数。问题是UC-01/03/04仍将“重复提交”并列在异常中，容易被后续细化为“一律报错”或重复执行。临床阻断、拒绝留痕、告警留存和队列补发的故障结果，也需要从具体触发步骤进入既定语义。

**最小建议：** 为实际适用的子目标列具名分支及来源，不重复发明规则：

| 分支类别 | 场景输出及不变量 | 已有依据 |
| --- | --- | --- |
| 相同业务意图/内容重试 | 重新授权后返回既有/可核对结果，不再创建业务或告警；返回病历仍记本次读取审计 | NFR-05、§8.2、C-10 |
| 同标识异内容 | 冲突，保留原内容和结果；修改后的独立新提交另按C-10评估 | §8.2、C-10 |

| 必需留痕不可靠 | 继续拒绝违规，说明未完成留痕/待核对；不虚报已记录 | FR-07.7、§8.2 |
| 队列不可用但本地告警/待发已保存 | 显示持久待发并进入恢复；不是已送达，也不等于留痕失败 | FR-07.3/07.7、UC-12 |

## 4. 补读共同原文口径后的最简表达建议
