# B方案最小技术预研执行计划

> 执行方式：superpowers:executing-plans，测试先行，末尾一次交叉审查；不在课程资料工作区另建Git项目或平行文档树。

**Goal:** 在独立真实MySQL/RabbitMQ上验证关键事务、隔离、幂等与恢复，并测量包含审计的完整HTTP响应。

**Architecture:** Django/DRF最小后端切片，InnoDB事务与SQL共享策略锁，事务Outbox和消费收据。仅loopback、专用库/账号、独立端口；第三方二进制/虚拟环境在用户ASCII缓存，实验源和证据在本目录。

**Tech Stack:** B优先预研；实际Python3.12.14、Django5.2.18、DRF3.16.1、MySQL8.4.13、RabbitMQ4.2.5、Erlang27.3.4.19。完整Python依赖锁在实验代码requirements.lock，兼容依据与安装证据在02。

**Spec:** 04设计目录06的PRE-01—03、03数据/接口、04时序及SRS v1.0（FE95C5BF…DAE8）。

- 只实现预研所需的接待、临床四类写入、读取/完整CSV、脱敏审计、最小必填护栏及恢复；不声称全部SR/FR/界面或完整控制编译器完成。
- 数据库、队列和HTTP只绑定127.0.0.1；凭据随机生成放cache/private且不打印；结束停本任务进程，保留复现实验数据。
- 正式AC-06仍要求题定全量数据、360并发10分钟、P95≤280ms和≥800/分钟；本轮短时探针不能代替。

## Review Focus

1. 同次重试先核当前账号与范围；同键换目标/模式/内容冲突，双首请求只有一笔。
2. 临床/采纳/用药四写路径审计失败全部回滚；护栏拒绝仍持久告警/待发，不吞告警。
3. 策略共享锁允许同店不同接诊并行，启用排他等待；误建竞争不允许新诊疗越过标记。
4. MQ停复、未确认/重投、消费落库后未ack不重复告警；完成回执不能被迟到worker退回。
5. 导出完整UTF-8、原版本/更正链、授权目标和实际审计一致，计时到全响应；跨店/管理无临床字节。

| 文件 | 职责 |

| 原始结果/ | red/green、版本锁、故障和逐请求负载、进程生命周期 |

服务接口固定为`write_medical(user, encounter_id, mode, operation_key, data, *, audit_fault=False, before_commit=None)`、`read_medical(user, encounter_id, *, audit_fault=False)`、`export_medical(user, ids, purpose, *, audit_fault=False)`。故障注入/同步hook只可实验测试内部传入，不从HTTP请求开放。返回`{status, code, ...引用或受控内容}`，错误不夹带临床正文。
