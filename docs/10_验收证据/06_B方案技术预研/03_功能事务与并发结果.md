# PRE-01 授权、事务与并发实验结果

> 2026-10-21。真实MySQL上的最小后端切片；不是完整系统或正式验收。输入为冻结SRS v1.0及04目录候选设计。

## 1. 实际结论

最后一轮完整实验测试集为 **37项通过，0失败，70.259秒**，运行入口总墙钟71.592秒，见[原始文本](%E5%8E%9F%E5%A7%8B%E7%BB%93%E6%9E%9C/pre01_final_race_green.txt)与[退出记录](%E5%8E%9F%E5%A7%8B%E7%BB%93%E6%9E%9C/pre01_final_race_green.json)。测试使用独立`t22_probe_test`，HTTP负载与MQ使用`t22_probe`，没有以SQLite或内存替身证明MySQL事务。

另外实际经过TCP代理丢弃已提交请求的HTTP响应，再用同键重试，观察到只有一条用药和一条写审计；正常停止并重启MySQL后，重启前后15个probe表、113754行的逐表行数与全行摘要全部相同。分别证明本轮已提交响应丢失的找回及正常重启数据保全，不能扩大为断电、强杀或所有未知提交窗口均已验证。

## 2. 已执行切片与证据界限

| 检查面 | 实际执行及断言 | 界限 |
| --- | --- | --- |
| 三角色及接诊归属 | 真实User/Profile、服务端角色与门店；同店其他医生、跨店、管理/前台读取临床内容均拒绝；管理只选脱敏字段 | 不是全部20个权限目标、全部字段投影与页面完成 |

| 前置护栏与告警 | 最小必填、用药追加及采纳条件在业务写入前判断；拒绝时保留命中/告警/待发，业务正文不变 | 规则为实验固定切片；完整控制包生成器、FloorSpec、治理审批未实现 |
| 幂等与撤权 | 同键同内容复用；换模式/目标/内容拒绝；两个首请求竞争同唯一键仅一次业务效果；旧结果返回前核当前账号 | 仅本切片写路径，不代表所有产品操作 |
| 策略锁 | 同店不同接诊可同时持共享锁；临床持锁时启用排他请求实际收到MySQL1205，释放后启用成功 | PolicyHead是PRE_FIXTURE并发令牌，不是已人工审批的运行规则 |
| 误建竞争 | 前台事务锁定同一接诊并标记误建时，临床真实锁等待超时；前台提交后新的诊疗写入因误建拒绝且无新用药 | 未声明所有可能调度与死锁组合已穷尽 |
| 完整授权CSV | 授权目标全选或整次拒绝；共享父记录锁，版本及更正链保留；生成及必需审计完成后提供；发送前重核当前角色/门店和完整范围 | 服务级完整性断言与HTTP响应断言相结合；大文件、分页和并发更正导出仍须专项验证 |
| HTTP边界 | 真会话/CSRF、固定模式、字段白名单；非法登录容器和导出UUID返回422；Content-Length回归通过 | 未做前端、浏览器及全部端点错误契约验收；路由检查辅助函数不等于发布门禁负向实测 |

## 4. 实际HTTP响应丢失与正常数据库重启

[HTTP响应丢失记录](%E5%8E%9F%E5%A7%8B%E7%BB%93%E6%9E%9C/http_commit_response_loss.json)对应`实验代码/http_response_loss.py`：一次性TCP代理转发请求，读到后端响应字节后向客户端转发0字节并关闭。客户端得到ConnectionError；数据库Operation已为200；同键直接HTTP重试复用原结果，用药数及写审计数均为1。原先仅在服务返回后关闭数据库连接的测试仍保留，但与该网络实验分开解释。

[重启比较](%E5%8E%9F%E5%A7%8B%E7%BB%93%E6%9E%9C/db_restart_comparison.json)对应`实验代码/snapshot_state.py`，按主键排序，对全部15个probe表的完整行计算摘要，不导出行正文或认证秘密。工程代理在HTTP停止、测试结束及前快照完成后正常关闭/启动同一MySQL数据目录；比较113754行全部一致。后续资源诊断又正常写入合成样本，因此比较是该重启检查点的证据，不要求当前数据库永远保持该行数。账号认证表不在该摘要范围，不能扩大说整个数据库所有表均逐行比较。

## 5. 首次迁移失败及可复现入口

初次使用未迁移应用同步建表，MySQL报1824（引用的auth_user尚不存在）；MQ最早一轮9项ERROR也由此引起，不能算TDD功能红灯。空库保护检查见到非空后拒绝重置。主代理核查只留下9组本次随机`mq-*`合成Store/PolicyHead，接诊、临床、操作等均为0，才进行本任务探针表的受限恢复。随后生成包含auth依赖的`probe/migrations/0001_initial.py`，正常迁移和测试成功。没有删除其他项目或用户业务数据。

`实验代码/prepare_schema.py`保留为这次一次性修复的历史证据，**不是常规初始化入口，不得对已有实验数据重跑**。正常复现顺序为：

1. 按[02环境说明](02_%E7%8E%AF%E5%A2%83%E4%B8%8E%E5%AE%98%E6%96%B9%E7%89%88%E6%9C%AC%E4%BE%9D%E6%8D%AE.md)启动专用MySQL/MQ；使用已锁定依赖的任务venv；连接凭据仍在用户缓存私密目录。
2. 在`实验代码`运行`manage.py migrate --noinput`，再执行`run_tests.py`并使用新的结果标签；测试库独立，使用`--keepdb`保留末次状态。
3. HTTP实验用`运行脚本/01_HTTP进程.ps1 -Action start`；停止使用同脚本`-Action stop`。MQ停复实验须独占生命周期窗口。
4. 结束使用缓存内`stop_all.ps1`；环境状态见02末尾。不要把私密连接、cookie或缓存全目录放入提交包。
