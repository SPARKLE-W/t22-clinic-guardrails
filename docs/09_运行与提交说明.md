# T22运行与提交说明（验收候选稿）

本文用于课程本地复现和最终提交清点。运行资料使用合成数据；宠物主人不登录，系统内部账号只有前台、医生和管理。最新源码复验见[第21阶段](10_验收证据/21_最终整体验收与提交整理/02_最终源码前后端复验.md)，最新负载问题与服务器状态快照见[第19阶段总结](10_验收证据/19_后端综合验收/32_当前问题与测试总结.md)。

本目录以[需规v1.0](03_%E9%9C%80%E6%B1%82%E8%A7%84%E6%A0%BC%E8%AF%B4%E6%98%8E%E4%B9%A6.md)为冻结需求基线；[架构与设计](04_%E8%AE%BE%E8%AE%A1%E4%B8%8E%E6%8E%A7%E5%88%B6%E6%96%87%E4%BB%B6/00_%E8%AE%BE%E8%AE%A1%E5%AF%BC%E8%88%AA%E4%B8%8E%E5%9F%BA%E7%BA%BF.md)、[可运行代码](../backend/README.md)、[测试与实测报告](06_%E6%B5%8B%E8%AF%95%E4%B8%8E%E5%AE%9E%E6%B5%8B%E6%8A%A5%E5%91%8A.md)、[AI过程留痕](07_AI%E4%BD%BF%E7%94%A8%E7%95%99%E7%97%95/)及[验收证据](10_%E9%AA%8C%E6%94%B6%E8%AF%81%E6%8D%AE/)分别承接设计、实现、结果和追溯。`03`、`06`及本说明均先维护Markdown源，再生成同名Word。[个人研究分析报告供本人审定稿](08_%E4%B8%AA%E4%BA%BA%E7%A0%94%E7%A9%B6%E5%88%86%E6%9E%90%E6%8A%A5%E5%91%8A.md)据本人真实提问/选择和授课建议整理，身份及T22§12真人证据由本人最后核定。

2026-10-24新增的《作业提交注意事项》按四类要求提交：①最终代码与测试结果文档；②需求、设计报告；③AI可执行规格相关文件及其介绍/说明；④每人一篇“AI时代如何进行软件开发”研究分析报告。第三类的[规格索引与说明](04_%E8%AE%BE%E8%AE%A1%E4%B8%8E%E6%8E%A7%E5%88%B6%E6%96%87%E4%BB%B6/21_AI%E5%8F%AF%E6%89%A7%E8%A1%8C%E8%A7%84%E6%A0%BC%E6%8F%90%E4%BA%A4%E7%B4%A2%E5%BC%95%E4%B8%8E%E8%AF%B4%E6%98%8E.md)已单列。第四类需展示各阶段采用的技术手段及提示词**或主要操作**，并覆盖AI影响、各阶段质量、人机协作/踩坑、T22任务书§12、本人亮点、授课建议及自由补充。该注意事项附实验报告封面字段，但没有给出唯一合订方式、页数、截止或提交平台；这些不能自行推定。

## 2. 环境与首次初始化

支持范围为Windows桌面Edge/Chrome、1366×768及以上。当前已验证的开发运行组合为Python 3.12、MySQL 8.4、RabbitMQ 4.2；精确Python依赖见`backend/requirements.lock`。本机开发用Django `runserver`，不是生产级上线方案；负载测量使用独立Waitress进程、独立合成库和端口。[严格冻结协议](10_%E9%AA%8C%E6%94%B6%E8%AF%81%E6%8D%AE/19_%E5%90%8E%E7%AB%AF%E7%BB%BC%E5%90%88%E9%AA%8C%E6%94%B6/01_%E6%AD%A3%E5%BC%8F%E8%B4%9F%E8%BD%BD%E6%B5%8B%E9%87%8F%E5%8D%8F%E8%AE%AE_v1.0.md)与[课程活跃会话试验](10_%E9%AA%8C%E6%94%B6%E8%AF%81%E6%8D%AE/19_%E5%90%8E%E7%AB%AF%E7%BB%BC%E5%90%88%E9%AA%8C%E6%94%B6/24_AC06%E8%AF%BE%E7%A8%8B%E5%8F%A3%E5%BE%84v1.1%E5%AE%8C%E6%95%B4%E9%AA%8C%E6%94%B6.md)是两种不同口径，不能互相替代。

1. 在仓库外创建Python虚拟环境，按`requirements.lock`安装依赖；在本机MySQL新建独立UTF-8数据库和仅可访问此库的应用账号。测试须另有可创建/删除的独立测试库权限，不把现有业务库当测试库。
2. 在仓库外建立私密应用配置JSON，设置环境变量`T22_APP_CONFIG`为其绝对路径。必需键包括`secret_key`及`database`下的`HOST`、`PORT`、`NAME`、`USER`、`PASSWORD`；可选连接设置为`CONN_MAX_AGE`（默认0）及`CONN_HEALTH_CHECKS`（默认false）。持久连接按工作线程占用数据库连接，配置前须核算MySQL连接额度。真实密钥和口令绝不写入文档、仓库或命令行回显。结构示例在[代码运行说明](../backend/README.md#治理应用)。
3. RabbitMQ创建仅本机回环可连的用户、虚拟主机和以`t22.app.`开头的专用队列；在仓库外建立配置JSON并设置`T22_MQ_CONFIG`。键为`host`、`port`、`virtual_host`、`user`、`password`、`queue`。Web不以队列暂时不可用为理由丢弃已提交的本地待发事件。
4. 进入`backend`，执行`python manage.py check`、`python manage.py migrate --noinput`。空库首次演示可运行`python manage.py seed_demo --credentials-file <仓库外新文件>`，生成两店/六个合成账号；该命令不用于已有库，也不自动批准/启用候选。示例账号口令文件留在本机私密目录，不随提交包分享。

历史共享合成应用库按[升级记录](10_验收证据/19_后端综合验收/11_共享演示库0009升级与冒烟.md)备份并应用了`clinic.0009`。这只是该次环境快照；其他机器须先备份、检查待应用迁移，再用同版代码启动。

## 3. 启动、演示与停止

先启动MySQL和RabbitMQ，再在`backend`目录的一个终端执行`python manage.py runserver 127.0.0.1:18730 --noreload`，浏览器打开`http://127.0.0.1:18730/app`。在另一个终端、相同代码和私密配置下执行`python manage.py alert_delivery --interval 5`，由它发布和消费持久待发告警。完整队列恢复测试需要实际RabbitMQ及`T22_MQ_CONFIG`；缺配置会明确跳过真实队列用例，不能声称完整通过。仅用本机合成账号和合成病历演示。

演示顺序：管理账号先生成候选、提交、检查、审批并手动启用本店规则/模板；前台账号建立本次接诊；分配的医生账号读取该接诊并记录诊断/检查、追加或关联更正用药、查看和处理护栏告警，按真实账号和理由决定采纳或不采纳明确标注的演示建议；管理账号只看本店脱敏汇总、治理/人机分工元数据并导出汇总，不能看诊断、处方、建议原文；医生只导出其负责病历和命中明细，前台无导出。需要演示建议时，先对**合成接诊**执行`python manage.py seed_demo_suggestions --encounter-ref <接诊UUID>`，不对真实临床数据运行。

停止时在两个前台终端分别按Ctrl+C，确认18730不再监听；MySQL/RabbitMQ按本机服务管理方式停止。仓库内`backend/运行脚本/01_本地应用.ps1`只管理自身启动的本机Web进程，数据库和队列仍单独管理；用户缓存下的本机路径不是提交包的一部分。

## 4. 验证与真实结果

在独立测试库运行`python manage.py check`、`python manage.py makemigrations --check --dry-run`和`python manage.py test vetcontrols governance clinic tests --noinput -v 2`。[最终源码复验](10_%E9%AA%8C%E6%94%B6%E8%AF%81%E6%8D%AE/21_%E6%9C%80%E7%BB%88%E6%95%B4%E4%BD%93%E9%AA%8C%E6%94%B6%E4%B8%8E%E6%8F%90%E4%BA%A4%E6%95%B4%E7%90%86/02_%E6%9C%80%E7%BB%88%E6%BA%90%E7%A0%81%E5%89%8D%E5%90%8E%E7%AB%AF%E5%A4%8D%E9%AA%8C.md)在对应验收快照的本机MySQL/RabbitMQ下为198项通过、生产Python语句覆盖率89%；前端语法和护栏测试通过。GitHub受保护主分支的PR `regression`通过才能合并。该次共享合成应用库应用`clinic.0009`及`governance.0002`；当时主分支的三类CSV完整接收、摘要一致且两项越权请求403，见[最终HTTP结果](10_%E9%AA%8C%E6%94%B6%E8%AF%81%E6%8D%AE/21_%E6%9C%80%E7%BB%88%E6%95%B4%E4%BD%93%E9%AA%8C%E6%94%B6%E4%B8%8E%E6%8F%90%E4%BA%A4%E6%95%B4%E7%90%86/02_%E6%9C%80%E7%BB%88%E6%BA%90%E7%A0%81%E5%89%8D%E5%90%8E%E7%AB%AF%E5%A4%8D%E9%AA%8C.md)。验证后18730已关闭。真实浏览器、队列停复与负载的各自证据见[06报告](06_%E6%B5%8B%E8%AF%95%E4%B8%8E%E5%AE%9E%E6%B5%8B%E6%8A%A5%E5%91%8A.md)。

**性能口径必须写清：**[课程活跃会话 v1.1](10_%E9%AA%8C%E6%94%B6%E8%AF%81%E6%8D%AE/19_%E5%90%8E%E7%AB%AF%E7%BB%BC%E5%90%88%E9%AA%8C%E6%94%B6/24_AC06%E8%AF%BE%E7%A8%8B%E5%8F%A3%E5%BE%84v1.1%E5%AE%8C%E6%95%B4%E9%AA%8C%E6%94%B6.md)在360独立会话、10分钟、每分钟≥800、零失败及七类P95≤280ms的预定范围内通过；19个业务账号复用，实际请求在途P95=3、峰值12。此前[严格冻结负载](10_%E9%AA%8C%E6%94%B6%E8%AF%81%E6%8D%AE/19_%E5%90%8E%E7%AB%AF%E7%BB%BC%E5%90%88%E9%AA%8C%E6%94%B6/05_%E6%AD%A3%E5%BC%8F%E8%B4%9F%E8%BD%BD%E7%AC%AC%E4%BA%8C%E8%BD%AE%E5%AE%9E%E6%B5%8B.md)的七类P95均超过280ms，优化后未同协议重测，**不得写成严格口径通过**；[原文与口径评估](10_%E9%AA%8C%E6%94%B6%E8%AF%81%E6%8D%AE/19_%E5%90%8E%E7%AB%AF%E7%BB%BC%E5%90%88%E9%AA%8C%E6%94%B6/21_AC06%E5%8E%9F%E6%96%87%E5%8F%A3%E5%BE%84%E4%B8%8E%E6%80%A7%E8%83%BD%E6%94%B9%E8%BF%9B%E5%86%B3%E7%AD%96.md)说明老师未定义并发含义。模板可选`x_`字段有后端API/CSV和隔离回归，但当前前端无动态编辑界面；Edge 2×设备缩放/683 CSS视口是本人接受的200%等效证据，实际浏览器菜单200%未验证；后端＋迁移4163行（含管理器状态迁移）仅在该明确范围内落入3200—4800区间，全栈另列7731行，不宣称全系统代码规模通过；维护性真人工日和业务错误码的所有输入组合仍未完整闭合。若主张严格口径达标，须按冻结的五店/6000宠物/约2万病历、360在途、600秒协议完整重测，不能挑短探针代替。
