# T22测试与实测报告（验收候选稿）

> 2026-10-25；依据需规v1.0、合并 PR #43 后的源码及第10目录原始证据。本文记录已实现功能、量化实测结果与各自的适用范围，不代替授课教师最终验收。所有诊疗、账号和负载资料均为明确标注的合成数据。

## 1. 对象、环境与复现范围

被测系统为前台、医生、管理三类内部账号的门诊护栏系统，含Django/DRF后端、MySQL、RabbitMQ及同源前端工作台。权限按门店和本次接待/接诊归属判定；宠物主人无登录入口。功能基线包含PR #40合并后的端点负例、PR #39的账号写入保护与可选模板字段；迁移包括`clinic.0009`及`governance.0002`。本机共享合成库已备份并应用两项迁移，从主分支启动的18730通过[三角色真实HTTP冒烟](10_%E9%AA%8C%E6%94%B6%E8%AF%81%E6%8D%AE/19_%E5%90%8E%E7%AB%AF%E7%BB%BC%E5%90%88%E9%AA%8C%E6%94%B6/20_%E5%85%B1%E4%BA%AB%E6%BC%94%E7%A4%BA%E5%BA%93%E6%B2%BB%E7%90%86%E8%BF%81%E7%A7%BB%E4%B8%8E%E6%8E%A5%E5%8F%A3%E5%86%92%E7%83%9F.md)，之后已关闭；正式负载在**独立的五店合成库**及18830测量，不能混作同一环境。

完整回归入口在`backend`目录：设置仓库外`T22_APP_CONFIG`和`T22_MQ_CONFIG`后执行`python manage.py check`、`python manage.py makemigrations --check --dry-run`、`python manage.py test vetcontrols governance clinic tests --noinput -v 1`。[最终源码前后端复验](10_%E9%AA%8C%E6%94%B6%E8%AF%81%E6%8D%AE/21_%E6%9C%80%E7%BB%88%E6%95%B4%E4%BD%93%E9%AA%8C%E6%94%B6%E4%B8%8E%E6%8F%90%E4%BA%A4%E6%95%B4%E7%90%86/02_%E6%9C%80%E7%BB%88%E6%BA%90%E7%A0%81%E5%89%8D%E5%90%8E%E7%AB%AF%E5%A4%8D%E9%AA%8C.md)在真实MySQL/RabbitMQ上得到**198项通过、0失败、0跳过**；同一源码单独执行覆盖率回归也通过198项，生产Python语句覆盖**2222/2492，89%**，统计`vetcontrols`、`governance`、`clinic`，排除测试、迁移和队列测试工具，见[逐文件原始报告](10_%E9%AA%8C%E6%94%B6%E8%AF%81%E6%8D%AE/21_%E6%9C%80%E7%BB%88%E6%95%B4%E4%BD%93%E9%AA%8C%E6%94%B6%E4%B8%8E%E6%8F%90%E4%BA%A4%E6%95%B4%E7%90%86/%E5%8E%9F%E5%A7%8B%E7%BB%93%E6%9E%9C/02_%E6%9C%80%E7%BB%88%E6%BA%90%E7%A0%81%E5%90%8E%E7%AB%AF%E8%A6%86%E7%9B%96%E7%8E%87.txt)。前端另通过`node --check`和原生工作台护栏测试；89%不代表前端或分支覆盖率。
