## 2. 机器结构与核对结果

顶层固定为 `catalog_version / kind / status / sources / mapping_decisions / authorization`。

authorization登记 `default / trusted_identity / unknown_fields / predicates / bindings / cross_store_clinical_refusal / other_undecided_event_visibility / projections / roles / projection_semantics / refusal_audit_scopes`。默认deny，身份server_session，未知字段reject；角色仅frontdesk、doctor、manager。宠物、主人、开发者、教师、代理及内部消费者均未新增为获权账号角色。

- 20条bindings逐条保留旧候选的goal、permission、role、row_predicate、输入投影、输出投影及server_selected_modes；权限键唯一。
- 每条增加mode_projections，明确各服务端固定模式的输入/输出，例如read仅使用Q投影，review/write/resolve使用对应W投影。客户端不通过提交permission或mode改换授权。
- 全部35个旧登记投影均有具体fields字典，共208个逻辑字段登记。字段含type、description；投影含source_ref、direction、constraints；需要时增加mode_fields或per_binding_fields。
- 有限逻辑类型为boolean、enum、integer、pagination、reference、reference_list、semantic_group、text、time_range、timestamp。semantic_group有界于说明和约束，绝不表示“实体任意字段”或整个对象转字典。

## 4. 已先报告并采用的技术映射

02§4声明原表是逻辑字段组，最终序列化由接口与数据字典承接。直接把合并行机械复制成可写字段会混淆方向。本轮先向主代理报告下述歧义，收到采用技术映射的回复后落盘；该回复是本轮实现协调，不记作用户新增业务批准。

1. Q-OWN的“时间等合法条件”未逐字段列完：仅登记encounter_ref、record_ref、time_range；未将“等”解释成任意筛选权。
2. Q/R/W合并行按方向拆分。W-GENERATE只输入定义需求，真实提交/审批/启用账号时间、校验/差异和内容绑定在R-GOVERNANCE或服务端生成约束；W-ASSIGNMENT只允许计划、指定版本、无正文事件引用及明确手工来源的依据，系统事件实际账号/角色/时间/标准结果由服务端解析。手工依据不能冒充系统事实。
3. Q-CREATE-AUX的doctor_options字段集为空，verify_pet_ref仅pet_ref；R-CREATE-AUX分别只给医生最小选择标识/显示名，或给定pet_ref与associable。无跨店参数、模糊宠物搜索、旧资料或主人联系方式。
4. Q-EXPORT-HIT共享名按permission分字段：医生可用scope/time_range/rule_ref/handling_state；管理仅time_range/rule_ref/handling_state，不接病例级scope。用mode_fields进一步固定诊疗record/correct、用药append/correct等字段集。
5. 病历版本、用药链、正式采纳责任、治理定义与分工元数据等保持有界semantic_group。它们不是已实现的内层JSON schema，也不能被编译器或后续API当作任意嵌套对象白名单。细化最终传输字段时须另行与02/接口/数据字典核对，不能静默放宽。

R-AUDIT的operator_role登记为已有事件的角色标记文本，不将内部执行事件强塞进三个账号角色枚举；它不产生新的可登录业务角色或权限。引用字段一律不附带正文展开权。实际账号/门店/归属/时间由可信上下文与服务端对象确定，不接受请求声明覆盖。
