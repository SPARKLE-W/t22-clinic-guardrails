# 独立视觉评审 v1 · T22「门诊护栏」

- 评审对象：前台 / 医生 / 管理三角色共用的工作台（验收基准 1366×768）
- 评审依据：油 ui《视觉与交互评审手册》第 1 节【全新界面与改版评审】，1–10 分
- 看过的证据：`02_最终界面/` 的 01–09、17、24 原图；25/26 只用于 1024/1920 补充核对；`00_评审/480_*.png` 与 `480_sheet.png`；`record.mp4`（9.07s，30fps）按 0.4s 抽帧看状态序列
- 本报告只评审，未修改任何界面或代码
- 边界：我只断言画面上能核对的东西；不说"流程已经走通"，也不猜后端。**动效没有按正常速度看过**，见 §4

## 0 速查清单

**[问题 1]** `08_医生_告警` / `20_医生_告警处理成功` 页头「告警」：标题字身中间被一条与字宽等长的删除线穿过（6 倍放大可见线压在字腰 y≈98），「告警」读成「生敬」；同页副标题、下划分隔线位置正常 → 标题只保留字，不与任何横线相交；验收：该页标题区放大 200%，无穿字线、无遮挡。

**[问题 2]** `08_医生_告警` 三张待处理卡：正文逐字相同（"本次写入被护栏阻断，病历未改变。请定位真实父接诊核对…"），唯二差别是 SR-03 / SR-02 与英文段名 reason / amount / unit；卡上没有"哪条记录、哪个值被拦、该改成什么" → 每张卡自己能说清被拦对象与下一步；验收：只读卡不跳页，就能回答"这条规则拦的是哪个字段的什么值"。

**[问题 3]** `11_管理_生成候选弹窗`：`选择文件 未选择任何文件` 是浏览器原生 file input（系统灰底、系统字体、系统按钮），是截到的屏里唯一一处没被皮肤覆盖的控件；主输入是一整块空白 JSON 文本域，首屏读不出这个候选会是什么 → 控件与全站同一套，且弹窗的主要阅读对象是"这次要生成的定义要点"而不是空域；验收：弹窗内无任何系统默认控件，首屏能看出将生成什么。

**[问题 4]** `17_医生_采纳建议弹窗` 弹窗底部：「用药·单位」输入框被固定底栏硬切，只露出约 20px 上边框；滚动区没有可见滚动条、渐隐或"下面还有"的提示 → 底栏与滚动区之间有可感知的分界，任何字段不被底栏切半；验收：1366×768 下不试滚也能看出下面还有字段，且最后一屏字段完整。

**[问题 5]** `24_前台_版本冲突` 弹窗提示条：提示写"请刷新后核对"，但弹窗内只有「取消 / 保存更正」，没有把最新版本取回当前弹窗的动作；照提示做只能取消→重开，已填内容随之丢失（截图里输入是被保住的，这点不该丢） → 提供"取回最新版本并保留已填内容"的路径，占用提示条右端现有空位，不新增区块；验收：出现 409 后，用户不必重打一遍就能基于新版再提交。

**[提升 1]** `02` / `05` / `09` 全站灰阶：标题黑，正文、次要信息、元数据挤在同一档浅灰（表格副行、右栏说明、审计表 `COMPLETED`），480 缩略图里除标题外几乎一片浅灰 → 拉出"正文 / 次要 / 元数据"三档，每屏的关键值（宠物名、规则名、失败结果）比周围重一档；验收：480 缩略图上不读字也能看出每屏的主值。

**[提升 2]** `02` / `03` / `05` / `12` / `24` 短编号：全站把 UUID 截成"8 位 + 3 位"（`d9e8835d-552`、`2761a92b-f83`、`a65c0bee-69d`），看着像被裁断的字符串 → 统一成 8 位单段或完整 UUID，所有出现处同一规则；验收：任意屏的编号都能被读成一个整体，不像溢出裁切。

**[提升 3]** `06_管理_治理台` 顶部四格与规则行：四格把"序号 / 数量 / 64 位哈希 / 状态"并排等宽，28px 的哈希 `9b8573ea` 成了最大字号，而真正该抢眼的"相对当前生效定义的变化：无变化"最小；八条规则行每条挂一个「不可削弱」，缩到 480 成一条粉色竖带 → 第一眼是"候选与当前生效差在哪"，哈希降为 mono 小字，同一属性只说一次（可为它腾位置删掉内层那组 10/6/35/0.2 指标块）；验收：480 缩略图第一眼落在候选 id 与两个版本的关系上，不是一排同色徽章。

**[提升 4]** `03` / `05` 右栏：四张同宽同款描边卡（前台读取范围 / 读取留痕 / 更正规则；本接诊状态 / 我的未处理告警），与中间的"纸"等权重，读起来是第二列面板而不是交接里定的"护栏批注" → 右栏收掉独立卡框，与记录纸共用同一条基线，只在真正相关处出现；验收：右栏看起来像写在这张病历纸右边的东西，不是另一列卡片。

**[提升 5]** 进入详情的过渡：从诊疗队列点进病历，中间与右栏整片清空，只剩内容区上方两行 12px 灰字（"正在读取权限范围…"），标题、卡框、编号都不在 → 先立住页头与卡框的骨架再填内容；验收：切换过程中标题 / 编号 / 卡框不动，只替换内容区。

**小问题（合一句，可一并处理）**：`02` 行尾「→」列无表头；`02` 每行重复「a_doctor / 接诊医生」两行；`02` 副标题「仅显示 A店（演示）由当前账号接待的资料」缺"中/里"，读起来像漏字；`03` 副标题与右栏「前台读取范围」讲同一件事；`06` / `08` 副标题各出现一个孤字（"号。"、"间。"）；`09` 每行「成功 / COMPLETED」双份、可见行全一样（共 100 条）；`06` 一条 64 位哈希整行摊在正文；`05` 同屏三个「追加用药」（页头、02、03）；`12`/`20`/`21` 的成功 toast 压在右栏内容上（盖住"更正规则"、"处理人"）；登录页页脚「Windows 桌面 · Edge / Chrome」是交付说明；1024 宽（25）左栏只剩「01/02」两个编号，导航名称全丢。

## 1 三秒测试（480 宽）

- **像哪一类**：像 2020 年代中期一套"医院内部病历 / 公文"系统；不是某个组件库的默认模板，也不是 Dribbble 上那种卡片后台。
- **第一眼看到什么**：一张带 01/02/03 编号段的记录纸，右上角一枚方框"正式病历"印章；左侧是案卷目录，右侧是窄栏。登录页第一眼是两行宋体大字"让每一次写入都有边界，让每一次读取都有留痕"。
- **遮字版**：交接没有提供遮字图，我用 480 缩略图近似（那个尺寸下文字已经不可读，剩下的就是骨架）：左窄栏 + 中间一张大纸 + 右窄栏，中间那张纸是明确主角，留白节奏成立——不是"四张等宽指标卡 + 满屏彩色胶囊"。
- 骨架在 `06_管理_治理台` 上失效：遮掉字以后剩下"顶部四格等宽条 + 右侧一条粉色徽章竖带"，退回到通用 dashboard 骨架。这一屏的三秒印象比另外两屏弱一档。

## 2 品类与标杆

**品类**：内部审计型 B 端工作台——三角色共用一份可审计、可更正的记录，界面本身就是"那张能被审计的纸"。

**同品类标杆在首屏怎么做**：EHR 的记录页（Elation / Epic / athena）是"一张可打印的表单 + 横向分节 + 段号 + 右侧 contextual 注释"；Linear / Sentry 这类工作台是"左队列 + 中间可滚动的对象本体 + 右侧元数据"，顶部只放对象身份与单一主操作。共识是：**一屏一个对象、一个主动作、右侧只放"跟这个对象此刻有关"的东西**。

**现有画面与共识的关系**：
- 对上的：`02`/`03`/`05` 的"队列—纸—注"三栏、段号、印章、版本链、错误态都在这套共识里；顶部对象身份（编号 / 建档时间 / 当前版本）放在右上、主动作贴着对象，距离合适。
- 偏离的：右栏做成四张等权卡片（元数据面板的默认做法），不是"批注"；`06` 用 dashboard 指标条做单对象页的页头，在一个"审批候选"的页面上，"生效序号 / 候选总数"这种全店口径的指标没有回答这一屏的问题（这个候选和生效版差在哪、能不能启用）。

**标杆素材的问题**（不影响本次打分，但影响方向探索的说服力）：交接 `00_标杆/` 的四张——Linear、Sentry、Elation、Practice Fusion——全是官网营销页或 404 页，没有一张是同品类工作台的实际画面，所以这一轮无法做"并排比素材与完成度"。要补，补的是它们的产品内页（Linear 的 issue 详情、Elation 的 chart 页），不是首页。

## 3 模型默认做法（逐条核对）

| 默认做法 | 是否出现 | 判断 |
| --- | --- | --- |
| 左大标题 + 右说明/图片的默认分栏 | 登录页是左右分栏 | 左栏是产品的三条不变式（角色边界 / 版本不可覆盖 / 阻断即留痕），紧接着三条落地，不是填位说明；不扣分。但右侧表单卡本身是通用登录卡，是全页最没性格的一块 |
| 处处圆角卡片、每层画线框 | 无圆角；记录卡内的线是内容 | 记录卡用线是对的（表格纸），右栏四张卡的描边是留白已经分开后还画的线，计一次（提升 4） |
| 单侧彩色粗边线装饰 | 没有 | — |
| 无来由的渐变 / 发光 / Emoji | 没有 | 全站图形只有方章、箭头、状态圆点；这一项做得干净 |
| 空泛晦涩的比喻文案 | 没有 | 主标语是具体的，副标题落到"前台只写接待、医生只写本人接诊、管理只写治理" |
| 配色没有产品依据 | 没有 | 纸 / 墨 / 深绿 / 锈红对得上"病历纸 + 审核章"；语义一致：红=被阻断 / 误建 / 告警，绿=正式 / 成功 / 主操作 |
| 字体与素材显旧 | 没有 | Noto Serif SC 标题 + 雅黑正文 + mono 编号有产品理由（病历 / 编号）；品牌感由方章、纸纹、编号承担，不是只靠一个绿按钮。代价是正文统一 12px 浅灰（提升 1） |
| 品牌字标挤占任务空间 | 每屏左上都有 | 交接明确允许，不扣分 |
| 截图工具的"默认做法提示" | 交接没给清单 | 只提到历史"质量目标行过长"已改；`06` 仍有一条 64 位哈希整行（见 §7） |

结论：这一版**不是**"在模型默认模板上换皮"。它有一个真方向，且方向落在版式里（段号、印章、版本链、页边规则），不是落在装饰上。

## 4 动效

**明确结论：我没看到动效。**本环境无法按正常速度播放 `record.mp4`，只能用 0.4s 抽帧看状态序列，所以下面的"能确认"只到"有没有状态切换"，不评手感。

- 抽到的序列：登录 → 诊疗队列 → **载入**（中间与右栏整片空白，只有两行灰字"正在读取权限范围…"）→ 病历详情 → 更正诊断与检查弹窗 → 关闭 → 追加用药弹窗 → 关闭。
- 能确认的事实：① 有一次页面级载入态，但它是"整片清空"；② 弹窗在一次 0.4s 采样内出现，并带背景压暗；③ 主操作有反馈——`12`/`20`/`21` 的静态截图里有右下角 toast（"接诊已建立"/"告警已登记处理结果"/"候选已启用"）；④ 录屏首帧已是完整登录版面（因此无法据此判断登录前有没有入场动效）。
- 不能确认：过渡时长与缓动、按钮按下态、弹窗关闭时的方向、toast 进出、hover / focus / 键盘态。因此**不判动效缺陷，也不写"动效通过"**。唯一写进提升的是那处能看见的跳变（提升 5）。

## 5 精致度

- **200%**：最粗糙的三处正好是问题 1（标题穿线）、问题 3（原生控件）、问题 4（底栏切字段）；其余控件边缘、描边、印章位置一致，卡片无阴影，1px 描边统一。
- **左边缘锚线**：正文块左缘 ≈264px、右栏左缘 ≈1028px，`02`/`03`/`05`/`06`/`09` 五屏一致，只有 2px 级噪声。整页共享 2 条垂直锚线，没有散成五六处——这一项是有秩序的。
- **中文断行 / 孤字**：`08` 副标题断成"…记录真实账号与时 / 间。"，`06` 副标题断成"…启用前再次核对生效序 / 号。"——两处都是一个孤字带句号掉到第二行。这不是正文宽度的问题，是页头说明的 max-width 定得太窄。
- **数字格式**：`02` 用 `10-23 09:45`、`09` 用 `2026-10-23 09:43:47`，前者是列表、后者是审计，说得通，不算不一致。
- **状态一致性**：`03`/`05` 页头都是"返回 + 两个动作"，`06` 只有一个主动作（顶层页，无返回），一致。
- **短编号**：`d9e8835d-552` 这种截法在全站重复出现（提升 2），是最容易被看成"裁切故障"的一处。

## 6 设计感

- **主角与占比**：480 下医生病历页的主角是中间那张记录纸（约占画面一半宽度）加标题；`02` 的主角是表；`06` 的主角被顶部四格、左侧候选列表、右侧徽章带三面分走（提升 3）。
- **最接近品类最好水平的一处**：`26` 的"用药链"——原项保留、`↳` 关联更正、时间与账号跟在行内，把"版本不可覆盖"这条业务规则直接排成了版式。这比任何徽章都更有说服力。
- **仍像组件库默认**：`11` 的弹窗（原生文件控件 + 空白 JSON）、`06` 顶部的四格指标条。
- **构图词**：登录＝扉页（分栏）；`02`＝案卷目录（表格）；`03`/`05`＝表单纸 + 页边注（分栏 + 编号段）；`06`＝主从（列表 + 详情）+ 指标条；`09`＝台账（表格）；`11`/`17`/`24`＝居中弹窗。"分栏"在 03/05 连用两次，但那是这个品类的工作方式（记录 + 批注），不算模板复读；真正复读的是"右栏四张卡"和"四格指标条"。
- **节奏与收尾**：中间那张纸是"开放画布 + 横线"，没有把每屏塞进卡片盒，这口气是通的；但右栏全是盒子，一屏里"纸"和"卡片"两种语言并存（提升 4）。`05` 以 04 段"版本留痕"收尾，不是"几个默认输入框收尾"。
- **真交互**：表单、弹窗、错误条都是真控件，`24` 的版本冲突条是真的服务端反馈，不是装饰。

## 7 精简与瑕疵

**填缝 / 无用文字**
1. 登录页页脚「Windows 桌面 · Edge / Chrome」——兼容性说明写进了界面，删。
2. `08`/`20` 三张告警卡正文逐字重复（问题 2）。
3. `03` 页面副标题与右栏第一张卡讲同一件事（谁可读），删一处：副标题只留"猫 · 接待资料由 a_frontdesk 读取"。
4. `02` 副标题「仅显示 A店（演示）由当前账号接待的资料」缺"中/里"，是病句。
5. `02` 每行的第二行「接诊医生」——列头已经说了，删。
6. `09` 的 `COMPLETED`——可见的每一行都在重复（共 100 条），且与"成功"同义，删。
7. `06` 的 64 位内容摘要整行——只留前 8 位 + 复制入口，别把哈希当正文。
8. `05` 同屏三个「追加用药」（页头 / 02 / 03）。若三者作用域真的不同，页头那个要写明"为本次接诊追加"。
9. `04` 的「新宠物编号」：一个 36 字符 UUID 占了一整行主位，右边跟「重新生成」，下面还有一句"编号由浏览器生成并提交…"。这是实现细节，前台要写的是名字和主诉；收成只读小字或折叠，把这一行让给物种 / 名称。

**该删该并的面板**
- 右栏四张卡并为"读取范围 / 留痕 / 规则"三行（提升 4）；
- `06` 内层那组 `10 / 6 / 35 / 0.2` 与顶部四格重复表达"规模"，并掉；
- `12`/`20`/`21` 的 toast 压在右栏数据上，若右下角继续用，右栏底部要留出安全区。

检验：删完之后，主角（记录纸 / 候选详情）会更大更强，而不是只是变空。

## 8 保留

1. **`26` 的用药链**：`↳` 关联更正、原项保留、时间与账号同行。它把"不可覆盖"这条规则画成了版式，是全站最有辨识度的一处，改版时不能磨平。
2. **`24` 的错误态**：版本冲突时表单内容原样保留，红色提示条只插在标题下，用户一眼知道"错的是版本，不是我的输入"。
3. **字体与印章的组合**：宋体标题 + 雅黑正文 + mono 编号 + 左上角方章，让"这是内部病历 / 公文"在 480 缩略图里也成立。
