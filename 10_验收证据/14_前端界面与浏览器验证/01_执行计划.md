# 第十四阶段 · 前端界面与浏览器验证：执行计划

> 2026-10-23。范围：三角色前端工作台、同源会话接入、真实接口操作与 1366×768 证据。不是正式性能/安全验收。

## 1. 问题与范围

用户要求使用 oil-ui 等工具完成前端开发并遵循工作流程。本轮把此前留给用户的前端补成一个可运行的同源工作台，验证它能否在真实账号、真实 CSRF、真实 JSON 接口下走通三角色主流程，并在 Windows 桌面 1366×768 下完成视觉检查。

不包含：MQ 实际恢复、人机分工登记、管理汇总、三类受限导出、正式 360 并发/10 分钟压测。前端不新增业务规则，不扩大任何角色字段范围。

## 2. 通过与不通过判据

通过：

- 三角色均可登录；角色入口只显示允许的操作。
- 前台建档、更正、误建；医生首次诊断、更正、用药追加/更正、建议采纳/不采纳、告警处理；管理候选生成/提交/审批/启用；至少各走通一次。
- 失败路径可区分：409 版本冲突、403 越权/目标不可用、401 失效、422 输入错误、503/断连结果待核对。
- 写入不在前端伪造成功；失败保留输入；业务变更带幂等键。
- 1366×768 下无横向溢出、遮挡关键操作或控制台错误；中文可读。
- 现有回归不退化。

不通过：任一主流程卡住；页面把失败显示为成功；直接 API 绕过角色边界；版本冲突被静默覆盖；关键操作被遮挡到无法触达。

## 4. 步骤

1. 读 13 交接、03 §8.1/C-09、实际路由与投影，确认字段、错误、幂等和角色边界。
2. 启动 MySQL 与 Django；确认 `/app` 返回壳并设置 CSRF Cookie；确认 `/api/session` 匿名/登录返回。
3. 做三个 1366×768 方向首屏并自选；落盘对比页。
4. 实现工作台；逐页接接口。
5. 用真实演示账号走三角色流程；用两个会话构造 409；记录实际结果。
6. 截图：1366×768 主状态、弹窗、错误态；1024/1920 补充；约 9 秒录屏。
7. 跑 `python manage.py test tests governance clinic --noinput`；跑 `manage.py check`。
8. 派发一位独立视觉评审；按报告修正可执行项。
9. 更新 13/15/README/导航/留痕；保存证据与限制。
