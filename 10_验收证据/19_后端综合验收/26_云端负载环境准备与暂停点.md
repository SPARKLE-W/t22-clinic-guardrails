# 云端负载环境准备与暂停点

> 更新日期：2026-10-31。本文记录ECS与严格TBR-05负载环境准备；不是严格性能验收结果。

## 环境与部署

- 阿里云 ECS：华中1（武汉本地地域），8 vCPU、32 GiB内存、100 GiB ESSD，Windows Server 2022 Datacenter；公网带宽按流量计费，峰值100 Mbps。
- 管理访问走SSH密钥；仅服务器公钥和本机专用私钥配对，私钥不上传。当前未通过公网开放应用、MySQL或AMQP端口。
- Python 3.12.10、VC++ v14 x64运行库、MySQL Server 8.4.13已安装。
- MySQL服务`T22MySQL`运行，使用独立数据目录`C:\ProgramData\T22\mysql\data_v1`，仅监听`127.0.0.1:3306`。Configurator非交互失败留下的旧`data`目录保留，不被服务使用。
- 固定源码为已提交Git版本`013d2a1`；隔离性能库为`t22_perf_strict_013d2a1`，配置与应用账号保存在仓库外受限目录。普通`t22_app`共享应用库不用于负载试验。

## 当前就绪度

- SSH身份验证、Django系统检查、迁移漂移检查和迁移通过。
- 隔离性能库迁移全部通过；固定种子`20261024`夹具完成：5店、6000宠物、20000接诊及病历、21000临床版本、2000条明确标注的合成演示建议。
- 夹具快照核对：12000个历史告警outbox事件、0条delivery receipt。历史outbox尚未由RabbitMQ真实投递，须在压测前清理/结清到正式协议要求的基线状态；不得伪造投递收据。
- RabbitMQ尚未启动；官方RabbitMQ 4.2.9安装包已在服务器，Erlang OTP 27.3.4.19官方下载至本机仍在进行。Waitress 3.0.2已安装在隔离Python环境。Web仅在服务器回环`127.0.0.1:18830`运行，并由SSH本地转发供探针访问；尚未启动并发发压或delivery worker。
- 尚无云端性能结果；所有先前机器上的课程口径负载或本机正式负载记录均不能代替当前ECS TBR-05测试。

## 接续顺序

1. 完成Erlang安装包下载并核验签名，SSH上传后安装；再安装RabbitMQ，确认服务版本、仅本机监听和独立应用凭据。
2. 按实际队列协议结清夹具历史outbox；用本次正式请求验证消息发布确认及持久回执，禁止人工伪造“已投递”。
3. 启动固定Waitress配置Web服务；本机通过SSH本地端口转发访问，执行授权冒烟、单请求分段和1/10/30/90/180/360在途阶梯。
4. 依据服务与发压两端资源、入口队列、SQL/锁/导出时间定位瓶颈；每轮只改一个原因类别，在独立数据快照/数据库上对比。
5. 只有预检证明负载端和服务端可进入正式窗口后，按TBR-05原样运行300秒预热和600秒正式采样。失败或超时照实纳入，不能删样或更改流量配比。

多轮执行目标与轮次记录见[27号计划](27_严格280ms多轮测试与改进执行计划.md)；基础数据库/源码验证详见[28号首验](28_云端环境与应用库首验.md)。
