# 临床状态与导出筛选专有码复核

> 2026-10-24；在独立 MySQL 测试库、真实 Django HTTP 入口执行。此表是[通用 34 路由负向矩阵](13_受保护接口通用负向矩阵增量.md)和[第一批专有码](16_端点专有错误码与拒绝审计增量.md)之后的增量证据。只记录已执行的触发条件；不把这些样本写成所有可能错误码已穷尽。

| 接口与触发条件 | HTTP／`error.code` | 核对的拒绝效果 | 可复跑测试 |
| --- | --- | --- | --- |
| 医生处理告警：请求体中的告警编号与路径不一致 | 403 `TARGET_UNAVAILABLE` | 原告警未处理；拒绝审计归实际医生账号及门店、关联原告警 | `clinic.test_writes.ClinicalWriteTests.test_alert_resolution_business_errors_keep_state_and_audit` |
| 医生处理告警：处理结果为空 | 422 `INPUT_INVALID` | 同上 | 同上 |
| 同一处理键换内容；已处理告警再用新键处理 | 409 `OPERATION_CONTENT_CONFLICT`；409 `STATE_CONFLICT` | 原处理结果不变，仅有一次成功操作；两次拒绝均留标准化原因 | 同上 |
| 医生追加用药：尚无正式病历；当前门店规则头无候选 | 409 `STATE_CONFLICT`；503 `POLICY_UNAVAILABLE` | 均未写入用药项或幂等操作；各有本店脱敏拒绝审计 | `clinic.test_medication.MedicationTests.test_no_record_or_policy_cannot_be_bypassed` |
| 医生采纳建议：同一键换理由；已有终态再采纳／不采纳 | 409 `OPERATION_CONTENT_CONFLICT`；409 `DECISION_FINAL` | 最终决定只有一条；未追加第二次决定或幂等操作；采纳和不采纳拒绝审计分开记录 | `clinic.test_suggestions.SuggestionTests.test_final_decision_replay_content_conflict_and_current_authorization` |
| 管理查询人机分工：非法阶段、比较状态或页码 | 422 `INPUT_INVALID` | 列表保持原数据；每次按真实管理账号和本店记录拒绝 | `clinic.test_collaboration.WorkDivisionTests.test_query_rejects_invalid_stage_comparison_and_page_with_audit` |
| 医生导出护栏命中明细：未知接诊编号、非法处理状态或反向日期 | 403 `TARGET_UNAVAILABLE`；422 `INPUT_INVALID` | 返回 JSON 错误、不返回 CSV；无导出申请；本店脱敏拒绝审计 | `clinic.test_exports.GuardExportTests.test_guard_export_business_errors_are_json_audited_and_have_no_file` |
| 管理导出护栏汇总：混入接诊编号或非法分组字段 | 422 `INPUT_FIELDS_INVALID`；422 `INPUT_INVALID` | 返回 JSON 错误、不返回 CSV；无导出申请；本店脱敏拒绝审计 | 同上 |

所有业务数据与账号均为合成测试夹具。`STATE_CONFLICT` 等是程序内部接口码，不是医学判断；业务拒绝不会由 RabbitMQ 送达状态自动变为医生已处理。测试结果和同轮覆盖率见[测试报告](../../06_测试与实测报告.md)及本目录原始结果。

**边界：**通用矩阵覆盖 34 个受保护路由的匿名、错误角色、错误方法，20 个 POST 的畸形 JSON 以及 15 个 GET 的未知查询字段；本文件只补上表中的专有状态／筛选条件。其余输入组合、突然断电、正式 360 在途负载和真实人工 AI 留痕仍分别按报告判定，不由本文件宣称通过。
