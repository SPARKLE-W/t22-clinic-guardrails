# 前端界面设计（病历纸方向）

> 2026-10-23。依据用户本次「使用 oil-ui 等工具完成前端开发」的要求，前端从后端联调页独立出来，做成同源单页工作台 `/app`。本文记录方向选择、界面结构、交互与联调约定；后端接口以[13前端对接](13_前端对接与接口交接.md)和实际代码为准。
>
> 当前状态：三角色主流程可运行，已连接真实会话、CSRF 与 JSON 接口；1366×768 截图与约 9 秒操作录屏在[第十四阶段](../10_验收证据/14_前端界面与浏览器验证/02_本批结果.md)。尚未做 Edge 独立复测、200% 缩放和正式性能验收。

## 1. 设计北极星

**界面是一张能被审计的病历纸。**

用户打开一个接诊，看到的不只是字段，而是一份可以被追溯、被更正、被阻断、被签字的记录：左栏是案卷目录，中间是带编号和印章的记录，右栏是压在页边的护栏批注。所有视觉选择都围绕「这条记录现在是什么状态、谁在什么时候动过它、下一次写入会不会被拦住」。

调性五个刻度：安静（低饱和纸色 + 两种语义色）、精致（1px 墨线、2px 圆角、严格对齐）、偏密（桌面工作台，1366 宽下尽量一屏看到当前对象与主动作）、中等分量（衬线标题 + 常规正文，不做大字报）、庄重（方角、印章、编号，不用插画和表情符号）。

## 2. 方向探索与选择

按 oil-ui 步骤 1，先做了三个不同骨架的 1366×768 首屏，统一放在
`10_验收证据/14_前端界面与浏览器验证/01_方向探索/`，对比页为 `style-explorer.html`：

| 方向 | 骨架与语言 | 结果 |
| --- | --- | --- |
| A 病历纸 | 纸色底、边缘编号、衬线标题、版本印章、右栏护栏批注 | 选定 |
| B 临床白 | 顶部导航、患者横幅、三栏圆角卡片、胶囊状态 | 未选：层级清楚，但接近通用 SaaS 后台，和「护栏/审计」的身份关系弱 |
| C 监护台 | 深色固定视口、等宽读数、信号色、方角面板 | 未选：辨识度强，但长诊断/主诉的连续阅读不如纸色底，且深色状态色过多会削弱「阻断」的唯一性 |

选择 A 的理由：

1. **任务适配**：产品的核心对象是带版本、更正、采纳和阻断的记录；案卷 + 页码 + 印章的语法直接对应这些关系，不需要另造隐喻。
2. **内容承载**：1366×768 下，232px 案卷栏 + 1fr 记录 + 306px 批注栏，记录区约 740px，中文正文每行约 45—50 字，适合长主诉与诊断。
3. **辨识度**：不采用「左侧栏 + 卡片网格 + 彩色胶囊」的后台默认骨架；编号、印章、版本节点和纸色底形成可复用的识别系统。
4. **实现代价**：纯 HTML/CSS/JS，无构建工具；颜色、字号、间距集中在 CSS 变量，后续换向只改 tokens 与布局类。

> 本轮没有把三个方向都做成完整产品；对比页保留三个首屏，最终实现只做 A。若后续想换向，B/C 的首屏和配色仍在对比页中，可直接作为改版基线。

## 3. 信息架构与路由

同源单页，hash 路由；登录后按角色只显示允许的入口，服务端仍逐请求鉴权。

| 角色 | 路由 | 页面 | 主操作 |
| --- | --- | --- | --- |
| 公共 | `/app` → 登录态 | 登录、会话核对 | 登录 / 退出 |
| 前台 | `#/receptions` | 接诊台（列表、时间范围、编号定位） | 新建接诊、打开接待 |
| 前台 | `#/receptions/new` | 建立接诊 | 新/已知宠物、核验、提交 |
| 前台 | `#/receptions/{id}` | 接待详情、版本链、误建状态 | 更正资料、标记误建 |
| 医生 | `#/clinical` | 诊疗队列 | 打开接诊 |
| 医生 | `#/clinical/{id}` | 病历、用药链、版本、采纳记录、建议 | 首次诊断、更正、用药、采纳/不采纳 |
| 医生 | `#/alerts` | 告警队列（待处理/已处理/全部） | 定位接诊、登记处理结果 |
| 管理 | `#/governance` | 规则管理（候选列表 + 定义/校验/历史） | 生成、提交、批准/驳回、启用 |
| 管理 | `#/summary` | 本店汇总（五类聚合、按规则/状态分组） | 只读，无病例下钻 |
| 管理 | `#/audit` | 操作记录（最近 100 条元数据） | 按病历/操作者筛选 |

前台没有临床正文入口；医生没有治理入口；管理没有病历正文入口。路由只做体验层的角色归位，直接调用接口仍由服务端 `protected` 权限入口拒绝。

## 4. 视觉系统

### 4.1 颜色

| Token | 值 | 用途 | 来源 |
| --- | --- | --- | --- |
| `--paper` | `#F3EFE4` | 工作区底色 | 病历纸的暖白，不用纯白屏幕 |
| `--sheet` | `#FCFAF4` | 记录纸面、表单、弹窗 | 纸面比底色亮一档 |
| `--ink` | `#1B241F` | 正文、标题、墨线 | 近黑绿，不用纯黑 |
| `--muted` | `#5E6A62` | 次级说明、时间、编号 | 与纸色的对比度满足正文可读 |
| `--green` | `#0C5A44` | 主操作、当前版本、通过 | 医疗记录里的深绿墨水 |
| `--rust` | `#9E3B29` | 阻断、误建、危险操作 | 印章红，压暗以适配纸色 |
| `--amber` | `#7A570E` | 待处理、待诊断 | 中间态，不抢阻断色 |

所有灰字均在纸色或纸面上检查过对比度；彩色只承担语义，不做装饰性大色块。

### 4.2 字体与尺度

- 标题/印章/大数字：`"Noto Serif SC", "Songti SC", "STSong", "SimSun", Georgia, serif`。
- 正文/控件：`"Microsoft YaHei", "PingFang SC", "Segoe UI", sans-serif`，正文 13.5px/1.7。
- 编号、时间、摘要、键值：`"Cascadia Mono", "Consolas", monospace`，约 10—11.5px。
- 页面标题 32px；记录标题 20—21px；诊断 19px/1.8；区块标题 16px；正文 13—14px；元数据 10—11.5px。
- 版心：主区最大 1260px；1366 下记录区约 740px、右栏 306px；16px 基准栅格，主要间距 8/12/16/20/24。

### 4.3 组件语法

- **记录纸**：1px `--line` 边、2px 顶线、3—4px 偏移阴影；不使用圆角卡片堆叠。
- **区块编号**：`01—05` 衬线数字挂在区块左侧 38px 槽位，形成案卷目录的节奏。
- **印章**：1.5px 边框、等宽小字、`rotate(-2deg)`；正式病历/已建档为绿，误建/阻断为锈红。只在记录级状态使用，不滥用。
- **按钮**：高 32px、2px 圆角、1px 墨线；主操作深绿实底，危险操作锈红描边，次操作纸面。按下位移 1px。
- **状态**：`chip` 统一 18px 高、2px 圆角；绿=正式/通过，琥珀=待处理/待诊断，锈红=阻断/误建，灰=中性/历史。
- **表单**：标签在上、错误在字段下；失败保留输入，不用 toast 代替字段错误。
- **弹窗**：最大宽 560/760，最大高 `100vh - 84px`，头部与底部固定、正文区滚动；阻断结果在弹窗内就地展开，保留原输入。

## 5. 关键页面与状态

### 5.1 登录与会话

- 左半：产品立场（写入有边界、读取有留痕）+ 三条原则；右半：账号/密码。
- 登录成功后 `GET /api/session` 取最小身份（账号、角色、门店引用与名称），不读 Cookie 内容。
- 会话失效（401）时提示重新登录；写操作失败不会清空已填输入。

### 5.2 前台

- 列表：时间范围（今日/近 7 天/全部）、按完整 UUID 定位、50 条分页、刷新；只显示接待资料；空列表保留新建入口。
- 建档：新宠物由浏览器生成 UUID 并提交；已知宠物必须先核验「本店可关联」；医生选项来自本店有效医生接口。
- 详情：接待资料 + 版本链 + 误建状态；更正必须携带当前版本引用和理由；误建标记不删除记录。
- 接待/病历编号可一键复制完整 UUID（剪贴板失败时回退到选择文本），减少手工转抄。
- 草稿按服务端确认的门店、账号、角色隔离；退出清空，身份切换只清理其他身份的缓存，历史无归属草稿不会被新账号继承；有未核对写入时表单顶部提示先核对。
- 右栏明确写出「临床正文不在前台读取范围」，这是权限事实，不是装饰说明。

### 5.3 医生

- 队列：只显示本人负责接诊；状态分为待诊断/正式病历 vN/误建，并显示用药、采纳数量；50 条分页，切时间范围回到第 1 页。
- 病历：接诊资料只读；诊断/检查、用药链（原项 + 关联更正）、版本链、采纳记录分区。
- 误建记录：禁止首次诊断、独立追加用药和建议采纳；既有用药仍保留「更正」入口，按 C-07/FR-02.5 做关联更正。
- 首次诊断、诊断更正、用药追加/更正都通过弹窗；更正必须绑定当前版本并填写理由。
- 采纳建议：展示来源标注（合成演示建议，非真实模型输出），预填诊断/检查/用药，采纳理由必填；有正式病历时带 `record_ref` 与 `original_version_ref`，无病历时生成首次病历。
- 告警：查看不自动处理；列表不展开字段值（沿用既有的告警元数据投影），卡面给出规则说明、命中字段、关联病历与「打开病历核对」；定位真实父接诊后才可登记结果；已处理显示处理人、时间与结果；页签显示待处理/已处理/全部计数。

### 5.4 管理

- 治理台：候选列表 + 定义摘要（红线、编码约束、字段投影、模板、质量目标）、校验结果、生成/提交/审批/启用历史。
- 四个动作分别在弹窗填写理由；批准携带内容摘要，启用携带生效序号；批准不等于启用。
- 审计只显示元数据；不提供诊断、主诉、处方、建议或自由文本理由；可按病历/操作者筛选，并按成功、拒绝、校验失败显示计数与前端筛选（不扩大服务端返回范围）。
- 本店汇总调用已交付的 `GET /api/reports/store-summary`：显示建档/误建/命中/告警/未处理五类数字，按规则或处理状态分组；无病例/事件下钻，失败不折成零，不使用前端估算。

## 6. 失败、幂等与并发

| 情况 | 界面行为 |
| --- | --- |
| 401 | 提示登录失效；保留表单输入；不清空页面 |
| 403 / 目标不可用 | 页面级错误或字段级提示；不猜测引用继续加载 |
| 409 版本冲突 | 弹窗内显示「记录版本已变化」，保留已填内容；提供「取回最新版本并保留已填内容」，重新取回后基于新版本提交；不自动覆盖、不循环重发 |
| 422 GUARD_BLOCKED | 弹窗内显示阻断横幅与 `event_ref`，写明「病历未改变」；提供查看告警与保留输入继续核对 |
| 422 普通输入错误 | 字段级提示；不声称已生成临床告警 |
| 503 / 断连 / 无法解析 | 显示「结果待核对」，保留原输入与幂等键；同一操作重试沿用原键；刷新后按表单上下文从 `sessionStorage` 恢复原键，输入与路径同账号/门店保存；HTTP 200 但响应无法解析也视为待核对 |
| 同一内容重试 | 同一表单上下文持久复用 `Idempotency-Key`；成功或 4xx 后清除；网络/5xx 保留；服务端拒绝重复或版本已变时提示先核对，不静默追加 |

客户端只做即时校验（必填、UUID 格式、理由非空、用药三项全有或全无），最终以服务端为准。页面不把隐藏按钮当权限，也不把客户端校验当护栏。

## 7. 动效

- 进入视图：`viewIn` 220—240ms，位移 5px + 淡入；同一工作台内切页不重播整页。
- 弹窗：遮罩淡入 160ms，对话框 220ms 从 `translateY(8px) scale(.985)` 到原位。
- 记录印章：保存成功后 `stampIn` 340ms，先放大再回正，表达「落章」而不是装饰。
- 列表行：hover 背景提亮、箭头右移 3px；不改变行高。
- 所有动效在 `prefers-reduced-motion: reduce` 下收缩到 0.001ms。

## 8. 响应与可访问性

- 1366×768 为正式基准；1920 下版心最大 1260，不把记录拉成超长行。
- ≤1180：案卷栏收窄为 150px，保留导航文字、隐藏案卷列表与页脚；≤960：案卷栏变为顶部横向导航，详情/治理改为单列；≤560：表单单列、隐藏门店与角色副信息。
- 表单控件都有可见 label；弹窗 `role="dialog"`、`aria-modal`，Esc 关闭，焦点落到第一个输入；Tab/Shift+Tab 在弹窗内循环，关闭后回到触发按钮；toast 使用 `aria-live="polite"`；可见焦点环；页面提供「跳到主要内容」，当前导航项带 `aria-current="page"`；复制按钮有 `aria-label`。
- 路由渲染使用代次隔离：每次读取先写骨架，视图在离屏容器渲染，只有仍属当前路由代次才提交 DOM；过期成功/失败不覆盖新页面。
- 列表页使用列表骨架（页头 + 工具条 + 行骨架），详情页使用纸框骨架，避免载入时从详情形状跳到列表。
- 所有数据插入都经 `esc()` 转义；不使用 `innerHTML` 拼接用户输入；采纳记录的诊断与检查均按文本渲染。

- 路由登记沿用统一权限入口扫描：三个新入口标记 `public_entry`；`python manage.py check` 无问题。

## 15. 面向门诊的文案减法与宠物门诊识别

用户反馈：登录页和子页面有过多课程/实现说明（“角色边界”“版本不可覆盖”“阻断即留痕”、Cookie/CSRF、服务端读取范围等），不像正常门诊工作台；并要求补充与宠物诊疗相关的视觉元素。本轮按“门诊同事每天用的工作台，而不是安全设计展示页”调整：

- 登录页删除大段宣言、三条原则和技术说明；改为宠物线稿、短欢迎语、三个业务标签、账号/密码/忘记密码。视觉使用暖纸色、鼠尾草绿、陶土色和爪印，不引入外部图片。
- 管理导航改为「规则管理 / 本店汇总 / 操作记录」；审计页默认只显示中文动作名，原始 action 移到 `title`，不再在表格正文暴露 `identity.login` 等实现码。
- 前台/医生列表和详情删除“本页只返回…直接请求也会被服务端拒绝”“读取留痕 clinical.read”等实现解释；保留必要业务提示（更正保留原版、误建不删除、告警需打开病历核对、汇总不含病例明细）。
- 接诊表单把“UUID / 浏览器生成 / 不包含主人信息”改成“宠物编号 / 自动生成 / 换一个”；宠物名称改为宠物昵称；主诉提示改成到院情况。
- 卡片、表格、按钮统一 5–7px 圆角；空态加淡爪印；登录页与品牌保留宠物线稿，不把技术编号或英文缩写当装饰。
- 仍然保留：审计、版本链、权限拒绝、失败不折零、真实接口；这些能力不因文案减法而删除，只是移到次要说明或可核对字段。
