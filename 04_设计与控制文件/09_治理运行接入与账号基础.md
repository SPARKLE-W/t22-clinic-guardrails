# 治理运行接入与账号基础

> 2026-10-22。阶段1的治理子批次已实现；本说明细化既有需求，不修改SRS。治理账号、MySQL事务和页面已接入，病历读取及完整诊疗仍待后续。

## 1. 模块和数据

05目录中`vetcontrols`继续只做静态编译；`vetapp`提供Django配置/路由；`governance`提供账号、治理模型/正式迁移、服务、默认拒绝入口、JSON接口和服务端模板。使用Django 5.2.18、mysqlclient 2.3.0及独立MySQL库；DRF 3.16.1作为B候选依赖已安装，本批接口直接使用Django JSON视图，尚未声称完成DRF序列化层或最终架构冻结。

Store/Account/Session提供实际门店、三角色、口令哈希、服务端会话。无公开注册、账号改派或Django admin；staff/superuser不绕过业务角色。Demand保存生成账号/时间/理由、摘要及校验报告；失败输入不保存原始定义，避免把越界正文存成管理可读原料。Candidate保存静态原包及摘要，运行状态单独保存；Review绑定具体摘要/真实账号/理由，Activation保留每次启用历史，PolicyHead维护本店当前候选与递增generation。Operation唯一键为账号/权限键/操作UUID。

候选内容没有编辑接口；调整内容须重新生成新候选。运行状态draft→submitted→approved或rejected；批准不改生效指针，只有手动activate成功才切换。允许同一个获准管理账号提交并审批，未新增双人制度。静态envelope.governance仍为draft_unsubmitted，不能用修改静态元数据冒充运行批准。

## 2. 身份、入口和具体请求

所有变更接口要求当前有效会话、CSRF、`Idempotency-Key` UUID和实际账号行重新核验；不接受自报actor/store/approval。服务端根据独立权限目录判断角色和本店范围。缺权限登记的视图由运行中间件拒绝，同时Django系统检查E001阻断发布；显式公开的仅登录页、登录及退出。没有临床全文路由或通用实体后台。

| 接口 | 权限/逻辑投影映射 | 具体请求 |
| --- | --- | --- |
| POST /api/login、/api/logout | 身份前置，不新增业务目标 | 登录仅username/password；CSRF同样适用 |
| GET /api/example-definition | governance.candidate.generate，W-GENERATE的演示定义辅助 | 只返回本店合成定义，不读取病历 |
| POST /api/candidates/generate | governance.candidate.generate；W-GENERATE→R-GOVERNANCE | definition、reason；definition为完整结构对象或原始JSON字符串，后者仍严格拒绝重复键 |
| POST /api/candidates/submit | 同一generate目标内的独立提交步骤，不增加角色/授权模式 | candidate_ref、reason；不能借此接口生成新定义 |
| GET /api/candidates、/{UUID} | governance.candidate.review/read；Q-GOVERNANCE→R-GOVERNANCE | 当前列表展示最近100项；详情含定义、校验、相对生效版本变化和治理历史 |
| POST /api/candidates/review | governance.candidate.review/review；W-REVIEW | candidate_ref、content_digest、decision=approve/reject、reason |
| POST /api/candidates/activate | governance.candidate.activate；W-ACTIVATE | candidate_ref、expected_generation、reason |
| GET /api/audit | audit.metadata.read；R-AUDIT | 当前仅最近100项本店脱敏事件；完整检索/分页随后承接UC07.2 |

definition包装对应W-GENERATE已有字段/模板/规则/规范/质量/来源语义组；content_digest对应具体content_version_ref；expected_generation是启用时的生效指针前提。输出中的运行状态、摘要、操作者/时间/理由/激活历史对应R-GOVERNANCE治理元数据组。没有开放任意JSON实体通配序列化；未知请求字段拒绝。

## 3. 原子性、并发、重试与拒绝

治理写事务按实际账号行→本店策略指针→候选/批准→业务审计及Operation结果执行。该顺序相较初步设计用账号行锁串行化同账号治理写意图，从而避免同操作并发抢占；不同管理账号启用则由同一PolicyHead行锁及expected_generation裁决。此为治理路径选择，不应机械套用到后续所有临床请求。

实际账号、当前权限及目标范围均在读取已完成Operation结果前重查。相同操作/相同规范内容返回原结果，换内容、目标或步骤冲突；失败事务不消耗操作标识。审计/操作结果与治理写同事务，任何必需审计写入失败均回滚。启用还要重新静态复核候选、核存储摘要、核批准摘要及当前策略代次；合法收紧后重算摘要也不能复用旧批准。历史候选、批准及启用事件不删除。

拒绝事件在失败事务之外保存。已能确认本店的目标及状态冲突按L关联本店/目标；跨店治理或上下文不明按U留安全事件，不凭C11擅自赋给请求店或目标店。管理审计只返回事件号/时间/事件店/账号角色/动作/结果/标准原因/无正文目标引用；不含自由文本理由、临床正文或输入包。读取必要审计保存成功才返回治理详情。

主要失败码：AUTH_REQUIRED=401；PERMISSION_DENIED/TARGET_UNAVAILABLE/SCOPE_DENIED=403；INPUT_INVALID/INPUT_FIELDS_INVALID/INVALID_REFERENCE/REASON_REQUIRED=422；状态/摘要/幂等/策略版本冲突=409；设施或提交不明=503。写入网络中断或提交不明时，页面保留输入及同一操作标识供核对；CSRF由框架直接403。页面提示区分提交、批准、启用，不自动串联。

## 4. 已验证与边界

原始测试、真实浏览器流程、HTTP和持久化核对集中在[第八阶段](../10_验收证据/08_治理与账号接入/01_执行计划.md)。实际MySQL使用InnoDB及TransactionTestCase；不以SQLite或只等待150ms代替锁证据，包含真实1205锁等待失败、释放后重试和两个管理账号竞争同代次仅一方成功。

演示账号由受控命令初始化，随机口令只写代码目录外的私密文件，数据库仅哈希。浏览器中自动化以演示管理账号验证批准/启用，理由明确“AI自动化功能验证、非真人审批/非真实门诊策略”；这不是用户或教师对规则的真实认可，也没有真实临床记录使用该演示指针。

本批只开放上述治理路径。医生/前台目前只有登录与身份页；临床读取/更正/建议/告警/导出、人机分工功能、完整审计查询、10个运行checker和全部20权限目标尚未实现。最终架构、AI来源和正式负载协议/性能验收仍待既定后续流程。
