# 人机分工登记与复核接口

> 2026-10-23 · 实现批次17。依据冻结需规FR-03、UC-11、§7.5及权限目录；本文细化序列化与技术实现，不修改需求。接口须随本批迁移0007部署后可用，代码合并不等于在用服务已升级。

## 1. 边界与数据

只允许当前门店管理账号。使用既定 `collaboration.assignment.write`（登记、列表、证据查询）与 `collaboration.assignment.review`（复核），统一权限入口、会话与CSRF沿用已有约定。当前账号/门店由服务端取得，客户端不得提交这些身份字段。

工作项引用是本店已存在的接诊编号或候选编号。没有临床内容读取权；管理可由既有脱敏审计的对象引用、治理列表取得编号。引用仅用于同店关联核验，不能打开临床正文。阶段与成功业务记录映射如下，访问日志不算实际决定证据：

| stage_ref | work_item_ref | 来源记录 | 可证明的维度 |
| --- | --- | --- | --- |
| content_generation | 接诊编号 | 已保存Suggestion | 已验证的演示来源→demo；未知来源不推测 |
| clinical_entry | 接诊编号 | ClinicalRevision | data_entry=doctor |
| medication_entry | 接诊编号 | MedicationEntry | data_entry=doctor |
| reception_entry | 接诊编号 | ReceptionRevision | data_entry=frontdesk |
| suggestion_decision | 接诊编号 | SuggestionDecision | data_entry/human_decision=doctor，结果adopted/declined |
| rule_review | 候选编号 | Review | data_entry/human_decision=manager，结果approve/reject |
| rule_activation | 候选编号 | Activation | data_entry/human_decision=manager |
| alert_handling | 接诊编号 | 已处理Alert | data_entry/human_decision=doctor |

`source_event_ref` 是上述业务记录的主键，类型由阶段确定；不是通用AuditEvent编号。Review主键就是候选编号。角色来自成功业务路径执行时强制的角色语义，不采用账号后来变更的当前角色。所有源查询只选择主键、账号、时间、规范化结果及生成来源必要元数据，不加载诊断、用药、建议正文、临床理由、告警处理自由文本。

## 2. 可直接对接的请求

- `GET /api/management/work-divisions`：列表/详情共用。可选 `work_item_ref, stage_ref, plan_version_ref, actual_version_ref, comparison_state, page`。page从1开始，每页50；返回items/page/page_size/total。过滤版本与比较状态只针对当前版本，不用历史匹配冒充当前状态；完整历史在条目中。
- `GET /api/management/work-divisions/evidence?work_item_ref=UUID&stage_ref=枚举`：必须两参数，返回该工作项该阶段可用的全部来源编号和脱敏执行元数据。不存在/跨店同样403。前端展示时间、账号、结果供管理选择本次要核对的实际记录，不自行选择“最像”的证据。
- `POST /api/management/work-divisions`：创建/追加新版本。必需JSON见下例；必须 `Idempotency-Key: UUID` 和CSRF。
- `POST /api/management/work-divisions/reviews`：针对当前版本追加人工复核，必须同样的幂等键与CSRF。

以下UUID均为合成占位，使用前需从真实本店记录/证据接口取得；不能原样当作真实业务：

```json
{
  "work_item_ref": "11111111-1111-4111-8111-111111111111",
  "stage_ref": "rule_review",
  "plan_version_ref": null,
  "actual_version_ref": null,
  "plan_dimensions": {"content_generation": null, "data_entry": "manager", "human_decision": "manager"},
  "source_event_refs": ["11111111-1111-4111-8111-111111111111"],
  "manual_actual_evidence": [],
  "reason": "登记本次规则审批分工"
}
```

首次两个版本引用为null；更新必须携带当前响应中两个引用。每次成功维护生成新的计划/实际版本对，旧快照、比较和复核保留。内容未改变也可形成一次有理由的维护记录，不覆盖旧历史。

三个计划维度键必须齐全，null代表不适用，至少一项适用。content_generation取human/ai/demo/rule_engine/unknown；data_entry取frontdesk/doctor/manager；human_decision取doctor/manager。将AI填为人工决定主体无效。unknown是明确资料未知，不足以证明一致。

source_event_refs为0—100个不重复UUID，须均属于同工作项/阶段。空列表可保存计划但比较为不可比较；显式不存在/错关联编号422，便于纠正输入。可从证据列表选择适用于本次实际版本的记录，不默默截取最新100条。

manual_actual_evidence为0—30项，每项严格为 `{dimension,value,source_ref}`，dimension/value按上述枚举，source_ref是1—200字符的ASCII依据编号（首字符字母或数字，其余可含字母、数字、点、下划线、冒号、斜线和短横线），不填写正文。服务端加 `kind=manager_declaration, recorded_by=当前账号`；记录时间由维护历史时间给出。人工声明单独保存，不能覆盖系统事件的账号、时间、角色或结果。外部依据未被系统核实时，声明不能补足缺失的系统生成来源，更不能把手工录入者当作原创者。后续真实模型/外部可信证据接入需新增经过验证的来源适配；本批不假装已接通。

复核请求必需字段：work_item_ref/stage_ref/plan_version_ref/actual_version_ref、`redacted_evidence`（当前响应source_event_refs原序列表）、`conclusion`、`reason`。conclusion取confirmed_consistent（仅一致）、confirmed_difference（仅待复核）、needs_followup（可比较但需继续调查）。不可比较时不能登记为已复核，需先补取得的实际证据再维护版本。复核不更改自动比较，更不批准原本无权限的操作。

## 3. 响应与并发

登记/复核响应为R-ASSIGNMENT：work_item_ref、stage_ref、plan_dimensions、plan_version_ref、actual_version_ref、actual_execution_metadata、source_event_refs、manual_evidence_provenance、comparison、maintenance_history、review_history。

- actual_execution_metadata每项：source_event_ref、stage_ref、actor_ref（无账号的生成来源为null）、actor_role、occurred_at、result、dimensions（三维分别给值/空）。无临床正文或理由。
- comparison：state=consistent/pending_review/not_comparable，missing_dimensions数组，differences数组（dimension/planned/actual值数组）。有缺失即不可比较，仍保留可证明的差异；全有依据且相符才一致。
- maintenance_history含每版两个版本引用、实际维护actor_ref/time/reason和该版完整脱敏快照；review_history含版本对、复核actor_ref/time/conclusion/reason。维护/复核理由是管理自己提交的文本，不是医生的临床理由。前端用文本节点显示所有文本。
- 页面“已复核”只看当前两个版本引用匹配的review_history，不能用任意旧历史或自动consistent显示已复核。旧版复核继续可查。
- 事务内锁当前账号及本店登记写入，版本校验、追加历史、审计与Operation同事务。审计失败503全部回滚；成功响应丢失用同键同内容重试返回原结果，不重复写入。新用户意图才分配新键。
- 不提供修改/删除历史API。详情GET不会证明页面之后未发生更新，写入始终以当前版本对校验。

## 4. 错误与验证

401 AUTH_REQUIRED；403 PERMISSION_DENIED/TARGET_UNAVAILABLE或CSRF；405 METHOD_NOT_ALLOWED；422 INPUT_FIELDS_INVALID/INPUT_INVALID/INVALID_REFERENCE/EVIDENCE_UNAVAILABLE；409 WORK_VERSION_CONFLICT/OPERATION_CONTENT_CONFLICT/EVIDENCE_INSUFFICIENT/EVIDENCE_VERSION_CONFLICT/REVIEW_CONCLUSION_CONFLICT；503 PERSISTENCE_UNCONFIRMED/AUDIT_UNAVAILABLE。未知/重复查询参数拒绝。业务拒绝在请求账号所属门店记录脱敏审计。

前端保留未确认提交的幂等键和原始内容；409刷新版本并由用户决定后续动作；503/超时不得直接显示成功或自动换键重提。此接口不改变前台/医生权限，不赋予管理临床跳转入口。
