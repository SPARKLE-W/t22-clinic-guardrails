# 病历写入与对应运行护栏

> 2026-10-22；沿用SRS v1.0、既有W-DIAGNOSIS/R-CLINICAL/Q-ALERT/W-ALERT/R-ALERT契约；本批不改冻结需求或角色权限底线。

## 路由与数据范围

| 路由 | 权限/模式 | 行和字段边界 |
| --- | --- | --- |
| POST /api/clinical/encounters/{UUID}/diagnosis | clinical.diagnosis.write / record | 当前有效医生、本店负责接诊；诊断、可选检查，不接受客户端账号、时间、门店、规则事实或其他临床对象 |
| POST 同前缀/diagnosis/corrections | clinical.diagnosis.write / correct | 同一归属；original_content_ref绑定既有ClinicalRecord，original_version_ref绑定当前ClinicalRevision，必填实际更正理由；只更新诊断/检查的新版本 |
| GET /api/clinical/alerts | clinical.alert.handle / read | Q-ALERT筛选后始终限D；显式告警/病历引用不扩权；输出限R-ALERT，不返回命中值或实体通配数据 |
| POST /api/clinical/alerts/{UUID}/resolution | clinical.alert.handle / resolve | 当前负责医生处理实际告警；路径和body alert_ref须一致；必填handling_result，实际账号和时间由服务端取得 |
| GET /api/clinical/alerts/{UUID}/encounter | clinical.read / detail | 仅以告警真实父Encounter定位，再调用既有read及D判定；输出既有R-RECEPTION/R-CLINICAL并执行读取审计，不扩大R-ALERT字段白名单 |

误建单不能record或借correct创建病历；原本有病历时允许原医生追加纠错版本、读取及处理已有告警。没有删除、改派或解除误建入口。更正不覆盖旧版本；省略检查说明时保留原检查，显式空串表示更正为空。

## 校验、事务与重试

写入锁顺序为账号→本店策略头→接诊。当前账号、门店和实际父归属先核验；每个请求的UUID幂等键绑定实际账号、权限、模式、目标、门店及内容摘要。已完成的成功或护栏阻断按原结果重放，重放前重新授权；不同内容复用键返回409。并发同键不重复写入，基于同一旧版本的独立更正仅一笔成功。

新病历持有接诊原模板，更正继续使用病历原模板；当前生效策略头另行绑定本次规则包。两包均核静态契约、内容摘要、所属店及批准/启用历史。临床校验记录ClinicalCheck保存模式、实际账号、原模板、当前策略/摘要、原内容版本、结果版本及各规则结果；后续更正不改写此前校验的目标版本。

当前诊断路径执行SR-02原模板必填检查；缺诊断/空白诊断为真实临床命中。SR-03/04在此不接受用药/建议的路径中标明不适用；SR-06/09由同事务审计、幂等结果和持久待发计划及实际提交保证，不能把写前计划写成提交后已成功。附加规则使用已批准包、注册条件和服务端事实；条件严格区分bool/integer，遍历全部操作数，不让短路掩盖未知事实。客户端不能提交事实。未知事实/不可执行规则、无有效策略或原模板无法核验均503并关闭写入，不生成虚假临床告警。

通过时，正式病历、版本、ClinicalCheck、审计/目标索引、幂等结果同事务；任一持久化失败全部回滚。阻断时保持原病历不变，在另一条同事务分支保存校验、GuardHit、未处理Alert、AlertOutbox待发、必要拒绝审计及幂等结果。必需持久化失败返回PERSISTENCE_UNCONFIRMED，不声称告警已保存；此时仍不写入违规病历。普通格式错误、身份/范围拒绝、版本冲突与设施故障分别记录，不统一算成临床命中。

一条规则对一个必填字段的实际命中形成一条GuardHit及Alert；同一提交若有不同规则分别命中，则分别留存。独立新提交再次命中新增校验/命中/告警；同次重试不新增。命中值留本地持久实体，当前R-ALERT只输出字段标识。告警首次阻断时可尚无ClinicalRecord，record_ref为空；仍有实际Encounter关联，可通过受控定位入口打开接诊，不制造空诊断来凑病历。

告警处理账号/结果/时间与投递状态独立，处理不删除命中，也不将待发改成已送达。按alert_ref、record_ref或告警定位路径拒绝时保留实际目标父关联及记录索引；跨店事件仍只归请求账号门店，动作保留实际clinical.read或clinical.alert.handle。

## 页面与当前限制

医生页提供首诊填写、更正历史、未处理告警持续提示、实际处理结果及“查看对应接诊”。字段显示诊断/检查的中文含义。已确认收到护栏阻断响应后，再次点击提交表示独立新提交；网络中断、5xx或响应未确认时保留原操作键用于核对，不把未确认误当失败后直接重建。

本批已持久本地待发，尚无RabbitMQ投递/确认/补发工作进程，不把pending说成已发送。处方/用药、AI建议采纳、人机分工、管理汇总和导出继续后续批次。静态允许的x_扩展字段尚未接到W-DIAGNOSIS运行投影，遇到该类模板失败关闭，不偷偷丢字段或扩大白名单；维护性扩展验收需后续补齐。本批未宣布10个运行检查器全部完成、正式性能达标、最终架构冻结或课程验收通过。
