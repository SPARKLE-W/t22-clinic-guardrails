## 1. 授权输入与固定边界

授权由服务端统一入口执行，前端隐藏按钮不构成授权。账号只有前台`frontdesk`、医生`doctor`、管理`manager`三类；宠物是诊疗对象，主人是相关方，开发者/教师/代理不列入运行权限。队列消费者、规则引擎和调度器通过内部受限调用工作，不领取管理或医生的临床权限。

| 设计名 | 可信来源与含义 | 明确不接受的替代 |
| --- | --- | --- |
| Principal | 已核验的当前账号标识、角色、所属门店；操作时重新确认其有效性 | 请求体自报账号、角色、门店；把已登录当成全部权限 |
| Encounter | 服务端一次接诊记录，含固定门店、接待前台、接诊医生、宠物关联、当次资料快照、模板引用及误建状态 | 客户端传入一套归属；按宠物编号推定所有接诊可读 |
| ClinicalLink | 病历、用药项、建议、告警到原Encounter的服务端关联；建议先绑定Encounter，存在病历时再关联同次病历 | 仅检查子对象ID存在，或用请求的病历ID替代实际父关联 |
| PolicySpec | 已登记permission key对应的角色、操作模式、行规则、输入/输出投影和状态规则 | 由调用者选择更弱的permission key，或通用`is_admin`放行 |
| AuditMeta | 由事件产生路径保留的标准化脱敏审计投影及事件所属门店 | 先取整份病历/原始请求日志再在界面隐藏字段 |

一次接诊成功后归属固定；新宠物或关联已知标识只建立本次关系，不授予全店宠物搜索、共享资料覆盖或历史合并读取。旧模板只决定历史字段解释，不豁免当前授权。未列键、未列模式、未列字段默认拒绝并记录。拒绝响应不返回无权目标的临床内容，也不回传原始口令、请求全文或SQL。

## 2. 行规则与事件归店标记

| 标记 | 判定条件或查询谓词 | 适用对象 |
| --- | --- | --- |
| F | `Encounter.store = Principal.store AND Encounter.receptionist = Principal.id` | 前台已有接诊的读、更正、误建 |
| F+ | 新建时门店/接待账号取Principal；所选医生由服务端核实为同店医生；接诊号/时间由服务端生成 | 前台建档；不是对全店已有接诊的查询权 |
| D | `Encounter.store = Principal.store AND Encounter.doctor = Principal.id` | 医生病历及其实际关联建议、用药、告警 |
| M | `Object.store = Principal.store`且对象为治理定义或分工元数据；不载入临床实体 | 管理候选、版本、分工 |
| MA | `AuditMeta.event_store = Principal.store`；只能选审计投影字段 | 管理审计；目标记录的门店不替代事件所属店 |
| MG | 仅聚合Principal所属店已授权的统计来源，先限店再聚合 | 管理统计/命中汇总导出；不返回明细行 |

下表20行的“拒绝归店”采用以下标记；事件留存和谁能查询事件是两个不同判断。

- **L**：操作范围及事件所属店已能由可信本店上下文确定，按该店留存脱敏元数据；不采用请求自报门店。同店他人记录拒绝的请求方与目标方本就在同店，不能因此取得他人病历。
- **X11**：可信账号跨店病历请求被拒，按C-11仅归请求账号所属店；该店管理只能读C-06元数据，目标店不额外获得此事件查看权。病历关联操作不得绕过此规则；目标引用无正文跳转。
- **U**：可信身份、事件归属缺失，或拒绝类别不在上述已确定归属内，先保留安全事件/必要恢复依据；不凭空分配给某店，不生成管理跨店可见权。C-11不被扩大成所有跨店治理事件的通用可见规则。若设计发现必须增加可见政策，应走需规变更，不能由实现默认授予。

所有行都必须保留拒绝及故障结果；L/X11描述已确定的门店可见范围，U不表示免记日志。事件设施故障仍拒绝原请求并报告留痕故障，不虚报“已记录”。

UC-01.1内的同店医生选择与已知宠物标识核验，属于建档的最小辅助交互，沿用`encounter.create`，不另授人员目录或宠物档案搜索键。UC-03的append/correct分别绑定服务端路由变体，两者只共享goal的键，不由payload自由选择覆盖原项；覆盖模式始终不存在。UC-12及UC-S01—03是内部行为，不作为可由任意业务账号独立调用的授权端点。身份核验是公开前置能力，其余受保护端点缺少登记时拒绝并阻断发布；账号初始化不据此变成管理创建/重置账号的权限。框架自带admin/调试后台不得形成临床全文或通用实体导出旁路。

## 4. 输入及字段投影白名单

下列是逻辑字段组，英文投影名用于设计对账；最终序列化字段/类型由接口和数据字典统一。只允许显式字段，不使用通配符或“整个对象转字典”。服务端写入的账号、时间、门店、归属、版本关联不是客户端可批量赋值的字段。模板可细化已允许临床/接待字段，但不能通过模板定义新增跨角色读取权。

### 4.1 前台及建档辅助

| 投影 | 明确允许 | 不允许/处理 |
| --- | --- | --- |
| W-CREATE | 系统新建或关联已知宠物标识的选择、种类、到院主诉、同店医生标识、可选称呼；有效模板引用按服务端核验 | 不接受指定接待账号/门店/时间/历史接诊归属；不接收诊断、处方、联系方式；宠物标识的生成/关联不读取旧接诊 |
| Q-CREATE-AUX / R-CREATE-AUX | 同店医生候选无跨店参数，仅输出可选医生标识及最小显示名；已知宠物关联核验仅接收给定标识，输出该标识及可关联/不可关联结果 | 服务端路由固定doctor_options或verify_pet_ref模式；不提供宠物模糊/全店搜索、旧种类/主诉/主人资料或历史接诊；不把核验变成其他记录读取权 |
| R-RECEPTION | 接诊标识、当次门店/接待账号/接诊医生、接诊时间、当次宠物标识/种类/主诉/可选称呼、误建标记与差错说明、获准当次普通资料版本/更正关联及实际账号/时间/理由、新旧接诊的无正文引用 | 不返回诊断/检查、处方/用药/剂量、建议/采纳理由、临床告警；新旧引用不自动载入另一次接诊 |
| W-RECEPTION | 当次种类/主诉/称呼的新值、原资料版本引用、更正理由 | 接诊号、宠物标识、门店、前台/医生归属均不可更正；未知字段拒绝，保留原值 |
| W-ERROR | 原接诊引用、误建理由；重建引用只能关联分别合法建立的新旧接诊 | 不接受删除/解除误建/自动撤销用药/转移临床内容 |
| 建档候选响应 | 同店医生的选择所需账号标识；已知宠物标识关联仅给核验结果和本次关联，不加载宠物档案 | 不列医生接诊列表、完整人员档案或全店宠物搜索结果；本次种类/主诉/称呼由本次输入确定，不自动复用无权历史 |

Q-OWN仅允许本次业务查询所需的接诊/病历引用及时间等合法条件，服务端强制叠加F或D；明确请求另一门店/账号的范围不能改写为本店成功。一般列表只在授权集合内过滤，零结果与无权引用/读取故障分别表达。医生读取关联R-RECEPTION不获得其写投影。

### 4.2 医生诊疗、建议及告警

| 投影 | 明确允许 | 责任/状态限制 |
| --- | --- | --- |
| R-CLINICAL | 病历/接诊引用、原模板版本及字段含义、诊断/检查、正式采纳内容及责任关联、处方/用药/剂量原项和追加更正链、获准既存版本/原值/新值/实际账号/时间/理由、误建状态与无正文新旧引用；关联R-RECEPTION只读 | 所有子项必须实际关联同一获准Encounter；新旧接诊不能借引用跨范围展开；模板升级仍按原版解释 |
| W-DIAGNOSIS | `record`：诊断说明、可选检查说明；`correct`：既存内容引用/版本、新内容、理由 | 正式提交至少有诊断说明；更正保留前后版本。误建不接受record，也不借correct新增独立诊疗 |
| W-MEDICATION | `append`：药品、用量、单位；`correct`：同病历原项引用、成组更正内容、理由 | 两模式均创建新项，服务端路由固定模式；更正关联原项。原操作者/时间不重写，实际更正者/时间取可信上下文；不得执行原项update/delete |
| R-SUGGESTION | 关联建议内容、来源、待决定/已采纳/未采纳状态、决定及其实际账号/时间、采纳理由或已填不采纳说明 | 仅D范围的建议登记；未采纳建议不丢弃，不作为正式病历内容混入导出 |
| W-ADOPT | 获准接诊/建议引用、已建病历引用（若有）、拟采纳内容、必填理由 | 实际医生账号取Principal；建议来源与Encounter关联取已保存记录；建议待决定、接诊非误建、模板/护栏通过后，登记/病历/审计同事务；首次建病历仍满足正式诊断等模板条件 |
| W-DECLINE | 获准接诊/建议引用、已建病历引用（若有）、不采纳决定、可选理由 | 实际账号取Principal；待决定进入不采纳；不创建或写入正式病历，误建的“禁止采纳”不能被扩大为删除已有建议 |
| R-ALERT | 告警/关联病历标识、规则编号、命中字段、未处理/已处理状态、已有实际处理账号/时间/结果，以及与原事件可核对的关联 | 只返回D范围；送达状态与处理状态独立；不返回其他医生的事件 |
| R-WRITE-RESULT | 本次操作状态、保存/决定引用、记录/版本或原项/更正项引用、实际责任关联 | 用于用药和建议决定的保存响应，不内嵌病历/建议正文；需要内容再走相应受控读取并记审计 |
| Q-ALERT / W-ALERT | 查看：获准病历/告警引用、规则/处理状态等筛选；处理：告警引用及实际处理结果 | 只对获准既存告警处理；缺结果拒绝，实际处理人/时间由服务端取得；原误建单既有告警仍可处理 |

正式写入校验还需取得获准目标的原模板与适用的已批准生效规则，记录本次版本和校验依据。缺有效规则、无法解释原模板或执行故障不回退隐藏默认配置。普通格式错误、身份拒绝、候选编译失败不自动计作病历运行护栏命中；实际运行护栏命中须另保留告警/拒绝及恢复依据。

### 4.3 管理定义、元数据与聚合

| 投影 | 明确允许 | 必须隔离的内容 |
| --- | --- | --- |
| W-GENERATE / R-GOVERNANCE | 输入包/候选标识和版本、本店字段/模板定义与必填要求、规则对象/操作/条件/拒绝结果、来源、编码规范/质量门禁、校验缺项/冲突、定义差异；提交/审批/启用的真实账号/时间/理由、内容绑定及当前生效/历史定义 | 只处理定义需求，不接入既存诊断/处方/建议正文作为生成或审批原料。治理理由是该治理步骤的说明，不转发医生理由 |
| W-REVIEW / W-ACTIVATE | 审批：具体候选及内容版本、批准/驳回、理由；启用：获批候选引用及理由 | 校验未过不能批准，内容变化不能复用旧批准；手动启用不能自动审批。未新增提交/审批必须不同账号的制度 |
| Q-GOVERNANCE | 本店候选/版本引用、状态、时间范围和分页 | 返回R-GOVERNANCE的定义、校验及版本差异，不载入临床正文；无额外治理导出权限 |
| Q-SUMMARY / R-SUMMARY | 本店时间范围；接诊建档数、误建数、命中数、告警数、未处理数及按规则/处理状态获准分组 | 接诊建档数含误建/重建，不作宠物去重或套用告警规则维度；不返回宠物身份/病历列表、命中值、主诉或自由文本临床原因 |
| Q-AUDIT / R-AUDIT | 时间、病历引用或操作者等合法筛选；返回事件号、时间、事件所属门店、操作者标识/角色、动作、结果、标准化原因、无正文目标引用 | 不含主诉/诊断/处方/建议、医生处理结果或理由正文、导出用途正文；不把目标引用实现成病历详情跳转。C-11事件显示门店为请求账号所属店 |
| W-ASSIGNMENT / R-ASSIGNMENT | 同工作项/阶段、计划责任维度和值/版本、实际生成方式、录入者与人工决定主体的分离元数据、实际账号/角色/时间、标准化事件结果、来源/事件无正文引用、差异/比较状态、维护/复核账号/时间/结论/理由及适用版本 | 仅采纳/审批/处理等执行元数据；“结果”指标准化执行结果，不是医生填写的治疗结果正文。原始建议、采纳理由、用药更正正文不进入该投影 |
| W-ASSIGNMENT-REVIEW | 工作项/阶段、计划/实际的指定版本、脱敏依据、真实人工结论与理由 | 资料不足不可比较，不能标已复核；计划/实际变更重比，旧复核不能套新版本；管理不能为了补证据读取临床原文 |
| Q-ASSIGNMENT | 本店工作项/阶段及计划/实际版本引用、比较状态和分页 | 只返回R-ASSIGNMENT元数据及复核历史；不按事件引用跳临床全文 |

管理仓储仅查询独立的定义对象、分工元数据、AuditMeta或聚合来源；不调用临床实体通用加载器，不作临床对象懒加载，不从原始payload提取自由文本再期待脱敏。实际执行方在合法操作完成时产生最小执行元数据，管理比较服务消费这些元数据；引用系统事件时，事件账号/角色/时间/结果由服务端解析，不能由管理输入改写成另一人的真实执行。手工登记来源保留其登记者及依据性质，不冒充自动取得的事件证据；没有来源依据则不可比较，不通过加入病历表来补齐。管理审计按目标引用筛选只比较引用值，不为解析引用而授权或加载目标正文。

### 4.4 导出专用投影

| 投影 | 输入及输出 | 完成/拒绝条件 |
| --- | --- | --- |
| Q-EXPORT-CLINICAL / CSV-CLINICAL | 必有获准病历范围及用途；UTF-8 CSV还原病历/接诊标识、模板版本/字段含义、诊断/检查、正式采纳内容及必要责任关联、处方追加更正链和操作者/时间/理由；保留误建状态和可解释关联 | 只包含D集合的正式病历；未采纳/待决定建议不混入正式内容。显式ID集合含一个无权目标则整次拒绝，不能静默删行。选择时间范围时先固定D再筛选 |
| Q-EXPORT-HIT / CSV-GUARD-DETAIL | 获准范围、时间及规则/处理状态筛选；医生输出获准事件/病历关联、规则号、命中字段、处理状态及已有真实处理账号/时间/结果 | 不新增“用途必填”；命中明细仍按D过滤；不附带全病历或其他接诊信息；导出不改变告警状态 |
| Q-EXPORT-HIT / CSV-GUARD-SUMMARY | 本店时间范围、规则/处理状态筛选；管理输出所用口径与按规则/状态汇总数量 | 只按MG聚合，不输出事件/病历/宠物级明细、临床命中值或自由文本原因；不新增审计元数据导出或接待资料导出权限 |

三类导出都复核当前身份/范围，生成完整授权集合并保存必需记录后才发送文件字节；病历导出记录账号/范围/用途/时间，命中导出记录账号/范围/时间。重新下载不借旧文件缓存绕过当前授权，返回病历数据仍记本次读取审计。服务端就绪、客户端完整接收、断连/结果待核对分开；不以任务受理代替完成，也不保证撤回已传片段。CSV不得只取当前页或静默截断，具体多行格式由接口设计承接。

## 5. 统一授权与投影伪代码

下面是算法说明，不是可运行代码。数据库访问均使用参数化条件；策略键和字段列表由服务端已校验的控制配置/登记提供，不拼接请求给出的列名或条件。权限规则本身不能被管理候选放宽既定红线。

```text
handle_registered_operation(endpoint, request, trusted_session):
    spec = endpoint_registry.lookup(endpoint)  # 服务端固定键/模式，不取request.permission
    if spec缺失或未挂授权:
        durable_reject(可信身份若有, sanitized_target_ref, NO_PERMISSION_GUARD)
        拒绝；发布扫描同时阻断该端点
    p = verify_current_identity(trusted_session)
    if p无效:
        durable_reject(unknown_identity, sanitized_target_ref, INVALID_IDENTITY, owner=U)
        拒绝，不查询临床正文
    if p.role不在spec.roles 或 请求模式不在spec.allowed_modes:
        reject_without_body(p, target_ref, ROLE_OR_ACTION_DENIED)
    if 输入/输出字段、筛选、归属声明超出spec白名单:
        reject_without_body(p, target_ref, FIELD_OR_SCOPE_DENIED)

    # 身份、行范围、字段三个条件都满足，才取得临床数据
    if spec是前台建档辅助:
        固定doctor_options或verify_pet_ref模式并检查Q-CREATE-AUX
        只返回R-CREATE-AUX；不建立接诊、不查旧接诊/主人/共享资料
    else if spec是前台新建:
        验证最小宠物建立/已知标识关联及同店医生候选，不查询旧病历
        新Encounter的store/receptionist/time由p及服务端生成
        doctor只取已核验同店候选；新接诊号由服务端生成
        事务内校验模板、必填、幂等并保存；返回R-RECEPTION
    else if spec是医生或前台的接诊关联操作:
        meta = load_authorization_metadata_only(target_ref)
        # 子项经实际ClinicalLink取得Encounter；不加载临床正文
        e = load_encounter_authorization_metadata(meta.encounter_ref)
        require F(p,e) 或 D(p,e)，具体选哪一个由spec决定
        require 请求中的每个子项/原版本/建议/告警实际归属于e
        scoped = 固定服务端行谓词及spec字段投影
    else if spec是管理元数据/定义/聚合:
        scoped = manager_metadata_or_aggregate_scope(p.store, spec)
        # 该路径不获取Clinical实体；审计按event_store过滤

    再核对当前权限及目标引用；所有显式目标均需获准
    retry = find_same_operation(p.id, spec.key, operation_ref)
    if retry存在:
        内容不同则冲突拒绝
        内容相同则取得原可核对结果；仍须当前授权，病历返回仍记本次读取审计
        # 不先拿“已采纳”终态拒绝同一操作的合法重试
        返回获准投影；不新增业务/告警

    在本次提交的一致性边界内重新核对状态、原版本及关联:
        普通更正保留旧值/新值/理由；处方append/correct都只追加
        误建阻止新增诊疗/用药append/采纳；既存纠错、旧告警处理和合法读保留
        建议新决定只从待决定进入采纳或不采纳；终态新改决定请求拒绝
        正式病历变更还须原模板+适用已批准生效护栏通过
        候选批准/启用、分工比较/复核按其版本/证据条件判断
    执行scoped查询或受约束变更:
        病历读取：必需审计持久成功后才返回白名单内容
        病历变更：业务、责任/采纳登记和相应审计同事务提交后才报成功
        运行护栏拒绝：原医疗内容不变；告警/拒绝/待发依据可靠保留
        其他操作：保存本操作必需留痕后返回获准投影
    故障/未知结果分别报告，不以空列表/已回滚/已成功代替核对
```

`load_authorization_metadata_only`只取目标类型/标识、实际接诊关联、固定归属、状态/版本等判定元数据，拒绝时不取诊断/建议/用药值。列表直接把行谓词下推查询；显式ID请求先验证全部ID，不通过“只查得到的部分”掩盖无权输入。合法空集合可以返回；设施故障不能伪装为空。

### 5.1 新病历与子对象的归属

```text
materialize_new_medical_record(p, encounter_ref, allowed_clinical_input):
    e = 服务端读取Encounter授权元数据
    require p.role=doctor AND D(p,e) AND e不是误建
    拒绝输入中的store/doctor/receptionist/其他Encounter归属赋值
    在同一提交边界复核e的状态/版本
    record.encounter_ref = e.id
    record的归属由e推导；若持久化冗余store/doctor，仅由e填充并约束一致
    模板引用经服务端验证；正式字段通过原模板/适用生效规则
    保存新病历与相应审计，返回该账号获准字段
```

首条病历不能因为“尚无病历可查”而跳过Encounter归属校验；子项的医疗归属也只沿真实父关联推导。建议上下文先绑定Encounter，Record引用可暂缺；存在Record后须验证它属于同一Encounter，不能靠选填Record引用挪动建议归属。首次诊疗或合法采纳需创建Record时沿用以上过程；不采纳只登记原建议/接诊关联，不为了登记创建病历。未满足正式诊断/原模板必填条件的采纳不能只凭建议和理由制造空病历。直接提供他人Encounter、伪造病历归属、替换建议/原处方ID均在写入前拒绝。建档与误建标记/临床提交发生并发时，状态检查及写入需用事务锁或原子版本条件维持同一前置条件，不能在检查后无条件写入；具体机制由整体事务设计选择。

### 5.2 拒绝留痕与管理可见归属

```text
reject_without_body(p, target_ref, normalized_reason):
    safe_ref = 保留可追踪的目标类型/标识，不展开正文或拼入任意请求文本
    if 身份可信 AND 属于跨店病历请求拒绝:
        event_store = p.store     # C-11；目标店不额外获权
    else if 既定本店上下文足以确定事件所属店:
        event_store = 可信本店上下文
    else:
        event_store = 未分配      # U，不据目标ID猜店或新增管理查看权
    可靠保存请求者、目标引用、动作、结果、标准化原因及时间
    按C-06生成AuditMeta；无可信归属的安全事件不放入门店管理查询
    若保存失败，保留故障/恢复依据并如实报留痕故障，原请求继续拒绝
    返回明确拒绝，不返回无权正文或目标宠物身份
```

拒绝记录不与已回滚的医疗写入一起消失；留痕提交路径与故障恢复由整体事务设计承接。C-11不会赋予A店管理读取B店记录的权限；A店管理看到的目标引用仅用于审计过滤。该管理再次拿引用调用病历入口，仍因角色拒绝，不因“审计可见”放行。未知身份事件仍需记录，但不能因看起来像A店请求就归A店或归目标B店。

## 6. 复杂度与性能边界

设N为接诊/病历元数据条数，C为单请求目标引用数，K为返回行数，F为每行白名单字段数，H为关联历史/更正项数，A为审计事件数，G为聚合输出组数。下列为算法量级，索引和缓存是设计候选，不是实测P95结论。

| 操作 | 时间复杂度及前提 | 空间/注意点 |
| --- | --- | --- |
| 键/角色/固定行属性比较 | 键映射查找期望O(1)，属性比较O(1) | 固定规则不按医院全部记录逐条扫描 |
| 单目标授权元数据查找 | 有主键/关联索引时O(log N)，子项到Encounter的固定层级关联仍为O(log N)量级；无索引最坏O(N) | O(1)元数据，不先取全文 |
| 多目标授权及显式集合导出范围检查 | 逐项索引核验O(C log N)，可批量查询但不能省略任一ID校验 | O(C)引用/核对状态；任一越权不静默删掉 |
| 已限范围列表及投影 | 合适范围索引时O(log N + K×F)；无合适索引最坏O(N + K×F) | 流式/分页O(页大小×F)，字段数不随整库增长；列表分页不能替代完整导出 |
| 单条病历及历史 | 元数据判定O(log N)，内容/历史处理O((K+H)×F) | 输出量是下界，不把任意长更正链声称O(1) |
| 本店审计查询 | 合适事件门店+病历/操作者+时间索引下O(log A + K×F)；无索引最坏O(A) | 仅AuditMeta；索引不提供临床访问能力 |
| 管理汇总/汇总CSV | 对本店筛选后S条统计来源聚合O(S)，输出O(G)；索引可缩小S，不保证固定时延 | 至少O(G)聚合状态；不加载S份病历实体 |
| CSV生成 | 已验证范围后O(输出字段/字符总量)，含历史及转义 | 可分块写完整临时产物；发送前完成必需留痕；不靠截断保证时延 |

状态/版本/幂等关联检索及审计持久化均有数据库成本；复杂度不能证明360并发P95≤280ms、10分钟无失败或吞吐≥800/分钟。正式计时含必需审计及完整文件响应；具体索引、资源、导出大小与请求占比在数据设计及TBR-05协议说明，不能为达标改小授权集合或漏掉错误样本。

## 7. 必须验证的负向样例

以下是未来测试设计样例，尚未执行。A/B表示两门店；FA1/FA2为A店两前台，DA1/DA2为A店两医生；EA1属于FA1/DA1，EA2属于FA2/DA2；EB1属于B店。管理MA/MB分别属A/B。用例需同时核响应、持久状态、审计归店和临床正文未外发；不能只断言HTTP状态。

| 样例 | 请求/构造 | 必须观察到的结果 |
| --- | --- | --- |
| NEG-01 跨店病历 | DA1请求EB1的病历/列表显式目标/建议或告警关联操作 | 拒绝且原业务不变；C-11事件仅归A，MA仅见脱敏元数据，MB无该事件新增权；响应与MA投影无B店宠物身份/正文 |
| NEG-02 同店他人 | DA1读取/更正EA2或导出EA1+EA2；FA1打开FA2接待资料 | 分别按D/F拒绝；显式导出集合不返回EA1的部分“成功文件”；同店拒绝可留本店事件但不开放EA2正文 |
| NEG-03 首条病历伪造 | DA1给尚无病历的EA2创建病历，体中写`doctor=DA1/store=A`；或给EA1写`store=B` | 必须以服务端Encounter判定；前者归属不符拒绝，后者受保护归属字段拒绝，不创建伪归属病历 |
| NEG-04 子项偷换 | DA1以EA1病历引用配EA2原处方/建议/告警ID | 实际父关联不符拒绝，不写更正/决定/处理结果；不回显EA2内容 |
| NEG-05 前台关联越界 | FA1用建档候选请求全店宠物搜索/医生病例列表，或传已知宠物号要求历史主诉/病历 | 仅保留最小选择/关联功能；请求扩展数据拒绝且记录，不加载其他接诊资料 |
| NEG-06 误建并发/新增 | EA1标误建后DA1新增诊断/新用药/采纳；或检查通过后与标记并发提交 | 新增/采纳拒绝；原记录保留，不自动撤药或关闭告警；并发不能绕过提交时状态条件 |
| NEG-07 误建可用出口 | 对误建EA1执行合法读取、既存诊疗纠错、原用药追加关联更正、处理旧告警、授权历史导出 | 上述路径仍可按原权限执行；不因统一“误建禁止全部”使纠错/告警成为死路；无删除/解标/新增治疗 |
| NEG-08 建档重绑 | FA1更正EA1时修改pet/store/frontdesk/doctor，或要求新旧引用自动加载EA2 | 拒绝，归属/原宠物关联不变；更正只能种类/主诉/称呼且留前后值/理由；重建另建且引用不扩权 |
| NEG-09 建议终态 | 已采纳建议新请求改为不采纳；已不采纳建议新请求采纳；同一原操作相同内容重试 | 新改决定请求因状态拒绝；原决定/正式病历不回改。合法同一操作重试返回可核对原结果、不重写业务；仍核当前权限 |
| NEG-10 导出角色/字段 | 前台导出；MA请求命中明细/宠物标识/命中值；医生缺病历导出用途 | 拒绝；管理只可汇总CSV。命中导出未填用途不因此错误拒绝；生成或必需留痕故障前无临床字节外发 |
