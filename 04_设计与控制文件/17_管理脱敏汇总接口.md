# 管理脱敏汇总接口

依据：冻结需规 UC-07.1、C-06/C-07/C-10、FR-05/07；权限目录 Q-SUMMARY/R-SUMMARY。实现只读接口，不开放病历下钻，不修改统计业务边界。

## 接口及授权

`GET /api/reports/store-summary`，同源服务器会话，仅当前有效管理账号可用，权限 `report.store_summary.read`。服务端当前账号决定门店；先限店，再聚合。前台和医生拒绝，匿名要求登录。不接受自报账号/门店、病历/宠物/接诊引用、临床值或用途。GET 不需要业务幂等键，读取成功仍写审计。

可选查询只有两项：

| 字段 | 约定 |
| --- | --- |
| time_range | URL 编码的 JSON 对象，含 from/to，均须为带时区日期时间；起点包含、终点不含；省略为全部时间，响应 null |
| group_by | rule 或 handling_state，省略为 rule；仅影响命中/告警分组，不对接诊数进行规则分组 |

未知字段、重复参数、非法时间或分组返回 422，不默默忽略。无页码/明细查询；分组完整返回当前范围的规则，处理状态分组固定返回未处理、已处理两行。

## 响应与字段映射

合成示例（不是实测演示库数量）：

```json
{"time_range":null,"encounter_created_count":2,"error_marked_count":1,"hit_count":2,"alert_count":2,"unhandled_count":1,"grouped_counts":{"group_by":"rule","items":[{"rule_ref":"SR-02","hit_count":2,"alert_count":2,"unhandled_count":1}]}}
```

`group_by=handling_state` 时 grouped_counts 为：

```json
{"group_by":"handling_state","items":[{"handling_state":"unhandled","alert_count":1},{"handling_state":"handled","alert_count":1}]}
```

顶层严格映射 R-SUMMARY 的七项；grouped_counts 为该逻辑组的具体传输结构，不是任意实体字段透传。响应不带宠物/接诊/病历/事件标识、账号、主诉、诊断、处方、命中值、AI建议或自由文本理由；rule_ref 仅为规则编号。

## 计数口径

- encounter_created_count：范围内实际建档条数，含误建与重建，不作去重宠物/有效就诊人数。
- error_marked_count：上述建档集合在读取时已标误建的条数；不是范围内发生“标记误建动作”的次数。
- hit_count：按校验事件时间筛选后的 GuardHit 独立命中条数；同操作重试不新增，同内容的新独立提交按既定规则留新历史。
- alert_count：上述命中对应的告警条数；未处理/已处理是读取时当前状态，不是期间处理次数。
- unhandled_count：上述告警中尚未登记处理终态的条数；处理不会删除告警或命中。
- 规则分组只聚合命中及一对一告警，传输尝试/收据不参与联表，所以重试和重投不放大数量。投递尝试数属于内部恢复信息，不扩入本接口的 R-SUMMARY 白名单。

接诊与校验各用自己的事实时间，不能按接诊创建时间漏掉期间对旧单的新校验。时间筛选与分组口径由契约固定；前端不自行合并第一页记录估计总数。

## 事务、故障与实现

服务在事务中重新核验并锁当前账号，数据库仅 SELECT 聚合所需键/计数字段，不加载临床正文。全局命中/告警/未处理总数由同一规则聚合结果求和，避免独立查询的分组与总数不一致。接诊统计和命中统计是两个读取语句；在现有 READ COMMITTED 下分别反映读取时已提交事实，不宣称跨所有业务表的历史时间快照。

必需读取审计与结果生成在同一事务；审计保存完成才交付 JSON。数据库/审计失败返回 503，不伪装成空集合或提供部分计数；正常空集合返回零。无响应缓存，无正文复制到审计，成功事件 target 为空、store 为当前账号门店。输入拒绝记录标准原因及当前门店。

状态：401 未登录，403 角色不符，405 非 GET，422 非法字段/时间/分组，503 数据库/审计暂不能确认。错误遵循已有 `{"ok":false,"error":{"code":"…"}}`。具体实现：`clinic/reports.py`；统一入口登记与发布扫描仍适用。无数据库迁移、无前端布局改动；机器契约见[05汇总OpenAPI](控制文件/05_管理汇总_openapi_v1.json)。

## 验证边界

定向测试涵盖两店隔离、精确字段、实际护栏命中与独立提交、角色/输入拒绝、半开时间、误建、处理分组、重复消息计数和数据库/审计失败。夹具中的跨店记录只用于验证聚合范围，未作为合法跨店模板写入产品流程。该接口交付不代表人机分工、CSV导出、正式数据量和性能验收已完成；证据见[第十六阶段](../10_验收证据/16_管理脱敏汇总/01_执行计划.md)。
