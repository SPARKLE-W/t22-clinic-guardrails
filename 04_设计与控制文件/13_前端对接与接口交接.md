# 前端对接与接口交接

> 2026-10-23，依据用户本次安排：使用 oil-ui 等工具完成前端开发。前端已作为同源单页工作台 `/app` 交付，后端只补最小会话恢复与静态入口；业务接口与权限边界不变。本文按当前代码核对已有路由；待实现项单列。冻结需规不变。

本轮增量：前端工作台、`GET /api/session`、`GET /app` 与静态资源入口已接入；建议后端三个端点仍按[14建议接口](14_演示建议与人工决定接口.md)交付，可导入[本批OpenAPI](控制文件/03_建议接口_openapi_v0.1.json)。全系统OpenAPI及机器可读契约仍待后续。

## 1. 工作边界

前端已按「病历纸」方向实现为原生 HTML/CSS/JS 单页工作台，源码在 `05_系统代码/frontend/`，同源入口 `/app`；设计说明见[15前端界面设计](15_前端界面设计.md)，浏览器证据见[第十四阶段](../10_验收证据/14_前端界面与浏览器验证/02_本批结果.md)。不引入构建工具和前端框架，避免为课程本地演示增加安装与发布步骤。

现有 `05_系统代码/governance/templates/` 和 `05_系统代码/clinic/templates/` 是已有联调页面，保留以便复现已有证据；不作为最终视觉规范，也不继续扩展布局和样式。新业务默认交付后端与 JSON 接口；前端按需接入，不要求同步维护旧模板。

同源集成仍是前提：新工作台由 Django 在同一来源提供页面并访问 `/api/`，没有配置跨域 CORS，也不关闭 CSRF。新增的 `/api/session` 只返回当前账号最小身份，不返回临床内容；页面不读 HttpOnly 会话 Cookie。正式验收仍须在 Windows Edge/Chrome 实际尺寸下操作；本轮只完成 Chromium 内核截图，算作界面证据，不能替代正式兼容验收。

三类运行角色仍为前台、医生、管理。前台只处理本店由其接待的资料；医生只处理本店由其负责接诊的临床内容；管理只处理治理、汇总与脱敏审计。宠物主人无登录端。页面隐藏按钮不代替后端鉴权，前端不得把管理接口扩成病历全文查询。

## 2. 连接与公共约定

| 项目 | 当前实际行为／对接要求 |
| --- | --- |
| 本机入口 | 新工作台 `http://127.0.0.1:18730/app`；原有联调页仍在 `/`。实际启动方式见05代码README；这不是已部署公网服务 |
| 路径 | 下表路径无末尾斜杠；以 `05_系统代码/vetapp/urls.py` 的实际注册为准，旧03设计表中的候选路径不代表已实现 |
| 登录 | Django服务器会话Cookie，非JWT；`POST /api/login` 输入 `username`、`password`，成功返回 `ok`、`username`、`role`、`store_ref`；`POST /api/logout` 退出 |
| 会话恢复 | `GET /api/session`：匿名返回 `{"authenticated":false}`；已登录返回 `username`、`role`、`store_ref`、`store_name`，不返回临床内容或其他账号 |
| 新工作台壳 | `GET /app`（或 `/app/`）返回 SPA 壳并调用 `ensure_csrf_cookie`；`GET /app/assets/<path>` 只读取 `frontend/assets`，路径逃逸返回 404；三个入口在第3节登记为公开入口 |
| CSRF | 先 `GET /app` 获得 `csrftoken` Cookie；POST发送 `X-CSRFToken`。登录会轮换CSRF token，后续请求重新读取Cookie，不一直复用登录前值 |
| 浏览器凭据 | 同源请求携带会话Cookie，现有页面使用 `credentials: 'same-origin'`；会话Cookie为HttpOnly，不能靠前端读取会话内容恢复身份 |
| 写请求 | JSON业务输入用 `Content-Type: application/json`；需幂等的业务变更另带 `Idempotency-Key`，值为一次操作生成的UUID。登录、退出、宠物编号核验不按业务变更要求该键 |
| 幂等 | 同操作、同内容重试沿用原键；响应中断或503时保留原输入和键核对，不自动新建操作。已明确收到GUARD_BLOCKED后修改内容或重新独立提交，使用新键；409不通过盲目换键掩盖版本冲突 |
| 可信字段 | 账号、门店、责任人、服务器时间及规则事实由后端取得；不允许前端自报事实替代授权。表单仅提交端点白名单字段 |
| 引用与时间 | 接诊、病历等引用通常是UUID，账号引用为数字；作为引用使用，不作为可自报的权限。带时区时间按响应解析，显示时转换为本地时间 |
| 响应 | 现有成功响应并非全部有 `ok: true`；按具体端点解析，不将缺少ok当失败。业务错误通常为 `{"ok":false,"error":{"code":"…"}}`；护栏阻断还含 `event_ref` |
| 非JSON | CSRF中间件拒绝、未知路由等可能返回HTML；先检查HTTP状态/内容类型，再解析JSON。网络中断或无法解析响应时显示结果待核对，不显示保存成功 |

当前支持同源集成，尚未配置跨域CORS或新的可信来源；Cookie的SameSite为Strict。设计工具可以先做合成数据原型。若工具生成独立前端应用，联调时优先由同一来源提供页面并转发 `/api/`；在确定实际运行方式后再细化，不能默认另一端口已能跨域携带身份。暂不开放任意来源、关闭CSRF或在页面内放数据库口令。

本轮已补**最小会话恢复接口**与**同源壳的 CSRF 初始化**：`GET /app` 初始化 `csrftoken`，`GET /api/session` 只返回当前账号身份。二者都不新增运行角色，也不返回临床内容；`governance/tests.py` 覆盖匿名/已登录/退出后的身份返回、壳的 CSRF Cookie、静态资源路径逃逸 404。纯 JSON 的全系统机器契约仍未提供，不能宣称已交付完整 OpenAPI。

## 3. 已实现接口目录

下列均为实际代码路由。受保护业务每次核验当前账号与数据范围；表中的角色只概括入口职责，不表示该角色可访问全店明细。

| 角色／用途 | 方法与实际路径 | 输入／返回要点 |
| --- | --- | --- |
| 公共／工作台壳 | GET `/app`、`/app/`、`/app/assets/{path}` | 返回 SPA 壳并初始化 CSRF Cookie；静态资源只读 `frontend/assets`；不做业务授权 |
| 身份／会话恢复 | GET `/api/session` | 匿名 `{"authenticated":false}`；已登录仅返回当前账号最小身份 |
| 身份 | POST `/api/login`、`/api/logout` | 登录字段及会话约定见上节 |
| 前台／同店医生选项 | GET `/api/encounters/create-options/doctors` | 无查询字段；返回 `doctor_options`，每项为 `doctor_ref`、`display_name` |
| 前台／已知宠物核验 | POST `/api/encounters/create-options/pet-reference-check` | `pet_ref`；只返回编号及 `associable`，无旧病历搜索 |
| 前台／建档 | POST `/api/encounters` | `pet_identity_choice` 为new/known、`pet_ref`、`species`、`complaint`、`doctor_ref`；`pet_name`、`template_ref` 可选；返回本次接待资料 |
| 前台／读取 | GET `/api/receptions`、`/api/receptions/{encounter_id}` | 仅当前前台接待资料，绝不返回临床正文 |
| 前台／资料更正 | POST `/api/encounters/{encounter_id}/corrections` | 待改的species/complaint/pet_name、`original_version_ref`、`reason`，不接受改派 |
| 前台／误建标记 | POST `/api/encounters/{encounter_id}/misregistration` | `reason`，可选 `rebuilt_encounter_ref`；保留原记录 |
| 医生／读取 | GET `/api/clinical/encounters`、`/api/clinical/encounters/{encounter_id}` | 当前负责接诊；接待资料只读，尚无正式病历时 `clinical: null` |
| 医生／首次诊断 | POST `/api/clinical/encounters/{encounter_id}/diagnosis` | `diagnosis`、可选 `examination`；模板声明时可选`extra_fields`对象；缺诊断会触发护栏，不能当草稿保存 |
| 医生／诊断更正 | POST `/api/clinical/encounters/{encounter_id}/diagnosis/corrections` | 待改诊断/检查或已声明的`extra_fields`、`original_content_ref`、`original_version_ref`、`reason`；保留旧版本 |
| 医生／用药追加 | POST `/api/clinical/encounters/{encounter_id}/medications` | `drug`、`amount`、`unit`；须已有正式病历，误建不能追加独立治疗 |
| 医生／用药更正 | POST `/api/clinical/encounters/{encounter_id}/medications/corrections` | 同上三字段及 `original_entry_ref`、`reason`；只追加关联项，原项不被覆盖 |
| 医生／告警 | GET `/api/clinical/alerts` | 当前负责范围的告警、处理状态；查看不会自动处理 |
| 医生／定位告警接诊 | GET `/api/clinical/alerts/{alert_id}/encounter` | 再次核验真实父接诊，返回受控临床读取结果 |
| 医生／处理告警 | POST `/api/clinical/alerts/{alert_id}/resolution` | `alert_ref`、`handling_result`；真实账号和时间由后端记录 |
| 医生／建议读取 | GET `/api/clinical/encounters/{encounter_id}/suggestions` | 已保存演示建议原文、来源和决定；无查询字段，不创建病历 |
| 医生／采纳建议 | POST `/api/clinical/suggestions/{suggestion_id}/adoption` | encounter_ref、suggestion_ref、adopted_content及采纳理由；已有病历绑定record_ref及当前版本；详见14 |
| 医生／不采纳 | POST `/api/clinical/suggestions/{suggestion_id}/decline` | encounter_ref、suggestion_ref、decision=declined；理由可选，建议和原文保留，不写临床内容 |
| 管理／演示定义 | GET `/api/example-definition` | 返回 `definition`；这是合成控制包输入，不是临床建议 |
| 管理／候选读取 | GET `/api/candidates`、`/api/candidates/{candidate_id}` | 本店最近100候选／详情；列表含generation与当前启用引用；不支持任意自造查询字段 |
| 管理／生成候选 | POST `/api/candidates/generate` | 定义与生成理由，字段细则见09治理设计；不自动提交或启用 |
| 管理／提交、审批、启用 | POST `/api/candidates/submit`、`/api/candidates/review`、`/api/candidates/activate` | 独立操作，版本/摘要绑定与理由等按09治理设计；批准不等于启用 |
| 管理／脱敏审计 | GET `/api/audit` | 可选 `record_ref`、`operator_ref`；最近100条获准元数据，无诊断、主诉、处方、建议或自由文本理由 |

接待/临床列表：`encounter_ref`、`time_range` 是业务筛选，`record_ref` 仅医生可用；`page` 为传输分页。`time_range` 是URL编码的JSON对象，from/to须带时区，起点包含、终点不含。显式引用与时间/分页混用会被拒绝；每页固定50、稳定排序，返回page/page_size/total。详情路径不接受查询参数。告警筛选按11设计及实际 `clinic/writes.py`，不可直接套接诊列表全部字段。

## 4. 用药请求示例与响应状态

以下仅为合成对接示例，字段形状依据当前实现，未把它伪装成新增实测结果。UUID占位需替换成已获准接口返回的实际引用；每次独立变更生成新的幂等键。

`POST /api/clinical/encounters/{encounter_id}/medications`

```json
{"drug":"合成演示用药","amount":"1","unit":"演示单位"}
```

成功HTTP 200返回以下形状，其中没有用药正文：

```json
{
  "saved_ref":"用药项UUID",
  "record_ref":"病历UUID",
  "operation_state":"saved",
  "original_entry_ref":null,
  "correction_entry_ref":null,
  "responsibility_metadata":{"actor_ref":123,"created_at":"2026-10-23T00:00:00+00:00"}
}
```

成功后再通过受控临床读取刷新 `clinical` 中的 `medication_chain`，呈现原项与完整更正链。不要只在前端把原行直接覆盖或把写响应伪装成已重新读取的病历。

| 状态 | 前端应有行为 |
| --- | --- |
| 200且为该端点成功结构 | 显示已保存；需要正文时重新读取对应获准资源 |
| 401 AUTH_REQUIRED／INVALID_CREDENTIALS | 提示登录失效或凭据错误，保留尚未提交输入；不把登录表单当成功数据 |
| 403 PERMISSION_DENIED／TARGET_UNAVAILABLE等 | 提示无权或目标不可用，不靠猜测引用继续加载；CSRF失败另按非JSON拒绝处理 |
| 409 OPERATION_CONTENT_CONFLICT／STATE_OR_VERSION_CONFLICT／STATE_CONFLICT等 | 保留输入，刷新获准状态后核对；不自动覆盖历史或循环重发 |
| 422 GUARD_BLOCKED | 正式病历未改，显示被阻断并引导查看告警；返回event_ref为校验事件引用 |
| 422普通输入错误 | 保留输入并提示检查格式/必需字段；不声称已生成临床告警 |
| 503／断连／无法解析响应 | 不显示成功；保留原幂等键核对结果。不存在独立结果查询接口时，按原请求重试并由服务端重新鉴权 |

以上原因码是当前实现中的示例，不是所有端点共享的穷尽枚举；后续逐批补端点—错误—测试对账。当前缺少可供工具直接导入的完整OpenAPI文档，不能宣称已交付机器可读契约。

## 6. 本批新增：管理脱敏汇总

`GET /api/reports/store-summary` 已实现，仅本店当前有效管理账号。可选 `time_range`（URL编码JSON，from/to须带时区、半开区间）及 `group_by=rule|handling_state`（默认rule）。不接受自报门店/账号、宠物/病历/接诊编号、规则筛选或明细请求。

返回 `time_range`、`encounter_created_count`、`error_marked_count`、`hit_count`、`alert_count`、`unhandled_count`、`grouped_counts`。规则分组仅 `rule_ref` 与数字；处理状态分组仅 `handling_state` 与 `alert_count`。响应不带临床正文或身份/事件明细。空集合为零，失败为错误；投递重试不增加计数，误建不从建档总数扣除。接诊按建档时间、命中/告警按校验时间；误建及处理状态取当前值。

错误：401未登录、403角色不符、405方法不符、422未知/重复参数或非法时间/分组、503数据库/审计未确认。GET无需幂等键，但有成功读取审计。完整字段、示例、口径与错误见[17汇总接口](17_管理脱敏汇总接口.md)；可导入[本批OpenAPI](控制文件/05_管理汇总_openapi_v1.json)。仅该端点，不冒充全系统OpenAPI。

前端可据此新增管理汇总入口；本后端批次没有修改布局/样式或伪造页面统计。后续人机分工端点见§8；CSV导出仍待交付。
